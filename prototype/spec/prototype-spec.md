# Muse 原型规格

本文档只记录原型代码无法自证的内容：设计决策、交互背后的行为契约、页面长什么样、交互怎么响应，以 `app/` 下的原型为准。

## 范围与边界

- 已实现闭环：登录/注册 → 作品库 → 探索故事设定 → 章节创作与修改 → 章节定稿 → 分阶段归档，可循环推进下一章与下一阶段。阶段规划作为幕后逻辑存在，不作为独立的用户页面。
- 移除“直接设定”（表单）模式，不再保留入口；故事设定统一通过探索完成。
- 探索页面已确认但静态原型无法表达的机制性需求（动态选题、推断、置信度、覆盖度判断），单独记录在 [探索页面待实现需求](exploration-pending-requirements.md)，不与本文档混写。

## 评审入口

- 探索页引导问答 / 自由讨论态：`#/projects/demo/explore?state=conversation`
- 作品库空状态 / 加载失败：`#/projects?state=empty`、`#/projects?state=error`
- 登录页状态：`?state=expired|invalid|locked`
- 文风锚点入口：`#/projects/demo/style-anchor`（未锚定）、`#/projects/demo/style-anchor?state=anchored`（已锚定）
- 全本通读视图：`#/projects/demo/readthrough`
- 模型接入设置（BYOK / 托管用量）：`#/settings/model-access`
- 阶段交界方向输入：`#/projects/demo/stage-direction`

## 品牌内容

- 品牌主张：`让每一个人，成为小说家。`
- 解释文案：`你参与设定、选择与修改，Agent 陪你把一个想法，一章章写成小说。`
- 以上文案与产品名 `Muse` 以本节为权威来源。

## 行为契约

探索与设定

- 探索分两种模式：`引导探索`由系统主导，纯选项式沉浸问答、一次聚焦一题；`自由探索`由用户主导，直接与 Agent 发散讨论。两者在新建作品时二选一，产出同一套故事设定与“整理为故事设定”链路。
- `引导探索`只呈现当前一题及其选项，不显示已答历史、无右侧线索区；第一题可用一句话自述作答，其余题提供“都不是这些”自答出口。
- `引导探索`支持问卷式前后翻页：上一题/下一题固定在页面底部导航栏，按可用性显示（第一题无“上一题”、已答进度之外无“下一题”，该侧留空占位保持两端布局），翻页不清除答案；翻回已答题会高亮上次所选、回填自述内容，重选只更新该题、不影响其后答案。
- `引导探索`答完最后一题后先进入“整理中”过渡态（约 1.2 秒），再弹出故事设定卡；若中途“回到探索页面”，过渡态复位，回到可翻页修改的收尾态。
- `自由探索`对话消息为只读连续记录，不折叠不拆分；需要调整的设定统一在右侧线索区直接修改。“给我一些方向”只把选择写入输入框，不替用户提交、也不替用户决定故事；勾选状态是会话级持续偏好，直到用户主动取消。“整理为故事设定”在首屏不可用，必须由用户补足信息并主动结束探索后才开放。
- 设定候选卡片可直接编辑；向同一探索 Agent 反馈后提升版本号并标出本轮变化项。
- “回到探索页面”需二次确认，确认后丢弃当前设定内容与修改记录。
- 待确认卡片在当前浏览器会话内恢复，刷新不回退到探索主界面；确认后清除待确认状态。

阶段与章节

- 确认故事设定后不跳转整本大纲页，也不展示阶段规划问答页或阶段计划确认弹窗；阶段规划在幕后完成，用户直接进入第一章创作。基础设定成为只读的全文指导上下文。
- 预计章节只是当前阶段的参考范围，不提前确定全书总章数与大结局位置。
- 阶段计划只形成章节骨架，详细章节计划作为后台写作输入生成，不额外要求用户确认。
- “改进本章”要求具体反馈并尽量保留现有内容；“重新生成”允许不填反馈并替换整章。
- 段落批注与整体点评共同作为“改进本章”的输入；重新生成整章后清除旧批注。
- “定稿本章”后，当前版本成为后续章节创作的正式上下文。

归档

- 归档页是故事档案统一入口：顶部展示已确认的故事设定（设定圣经），下方是分阶段的章节归档。
- 归档页首屏为清爽概览：设定圣经与各阶段均默认收起，点击行标题展开/收起（带高度动画），状态互相独立、由用户自由控制。
- 章节凝练归档（事件、人物变化、新增事实与线索、未解决悬念、章末状态）既供回顾，也作为后续章节的长期上下文。
- 第二阶段数据仅用于多阶段排版预览，其下一章操作只表达布局，不进入真实创作流程。

文风锚点（对应 PRD 模块 2 · FR16 · §7.1 红线验收前提；就绪报告 UX-ALIGN-01 新增）

- 文风锚点入口提供两种锚定方式：`从样本库选`（预置样本卡片，单选）与`粘贴我的范文`（≥20 字才可抽取），二者互斥切换。
- 抽取文风后进入`已锚定`态，展示作品级 `style_profile` 五维只读结果：人称、语气、句式节奏、意象密度、段落长度倾向；提供`重新选择`与`带着这个文风开始写`两个出口。
- `style_profile` 是后续所有正文生成的文风锚，也是行为红线“像不像用户要的味道”的验收基准。样本库内容与抽取结果在原型中为线框占位，真实抽取由后端实现。

全本通读（对应 PRD 模块 5 · FR26 · V1）

- 通读视图按已定稿章节顺序通读，仅供阅读，不含批注或编辑。章节正文沿用创作页的 serif 排版与首行缩进。
- 长章分页：单章正文按固定条数分页（每页若干段），底部「上一页 / 下一页」翻页并显示「本章 P / 共 Q 页」；翻过本章末页自动进入下一章第一页、从本章首页往前回到上一章末页，实现跨章连续通读；全书首页 / 末页两端翻页按钮置灰。
- 选章直达：正文上方的章节大标题本身即选章入口（标题右侧带 ▾ 提示、悬停反馈），点击标题即可切换到任意章的第一页，无需另设顶栏下拉、也无需逐页翻。
- 章节数据与分页在原型中为线框占位，真实数据来自各章定稿正文。

模型接入 · BYOK / 托管用量（对应 PRD 模块 0 · FR4）

- 模型接入设置分两态互斥切换：`Muse 托管（默认）`展示今日免费额度用量条（已用/上限，线框占位值，额度上限待盲测出单章成本后定档）；`绑定自有 Key`提供 API Key 输入与模型提供方选择。
- 托管态明示“写作过程中不会弹付费墙”；BYOK 态明示绑定后成本自付、不再计免费额度、密钥真实环境加密存储。
- 入口从作品库进入；额度数值、Key 存储在原型中均为演示占位，不做真实校验或上传。

阶段交界方向输入（对应 PRD 模块 3 · FR22）

- 一个阶段章节写完、进入下一阶段前，出现极轻、可跳过的方向输入过渡态：“这一段想往哪走？”，用户可写一句方向、也可`直接继续`（不填无感）。
- 该页含`我想开始收尾了`弱化入口，是用户主动声明进入收尾阶段的唯一控制点，不可省略。
- 平时跳过不打断“探索确认设定后无缝进第一章”的默认流程；方向文本作为下一阶段规划的幕后输入，不强制用户确认。
