## EXP-P01 建立问题原型库与动态选题机制

### 目标

探索模式不使用固定问题清单机械提问。系统需要通过有趣、间接甚至抽象的问题理解用户真正想写的小说，体验可以借鉴人格测试通过答案推断倾向的方式。

### 问题原型覆盖方向

- 情绪偏好：用户希望读者感到压抑、温暖、紧张还是震撼。
- 人物选择：用户更关注主动改变世界的人，还是被世界推动的人。
- 冲突偏好：人与人、人与制度、人与环境、人与自身。
- 世界规则：现实世界、轻度异常、完整架空。
- 叙事体验：解谜、冒险、关系变化、成长、命运感。
- 道德倾向：明确善恶、灰度选择、没有正确答案。
- 写作边界：不希望出现的题材、尺度和结局。

### 问题示例

> 一座城市允许每个人删除一段记忆，但只能删除一次。你的主角会立即使用、永远不用，还是替别人做决定？

该问题可以同时帮助判断世界规则、人物性格、道德困境和故事气质，不直接询问“你想写什么类型”。

### 问题原型库的组成

1. 问题原型：定义可以从哪些角度发问，以及适合在什么上下文中使用。
2. 推断标签：定义不同回答可能说明的创作偏好，不把单次回答直接等同于最终结论。
3. 追问策略：根据已有信息决定继续确认、换角度验证，或跳过已经足够明确的部分。

### 运行规则

- Explorer Agent 根据当前对话、已推断结果和置信度动态选择下一个问题。
- 问题顺序和数量不固定，不要求所有用户回答同一组题目。
- 同一结论可以从多个角度交叉验证，避免根据一道抽象题过度推断。
- “给我一些方向”提供的是当前问题的可选思考方向，不替用户直接确定答案。

### 当前原型差距

当前原型使用预设问题数组和固定顺序，仅用于验证页面布局、连续问答和反馈交互，不代表问题原型库已经实现。

## EXP-P02 以设定结果覆盖度决定探索是否完成

### 目标

不规定用户必须回答五题、十题或某一套固定问题。系统应判断整理故事设定所需的结果是否已经充分形成，再决定继续追问还是允许进入设定确认阶段。

### 基础设定必须覆盖的结果

- 故事的核心吸引力。
- 主角及其核心欲望。
- 主要阻力或冲突。
- 世界中最关键的规则。
- 故事整体气质。
- 用户希望获得的阅读体验。

### 辅助结果

- 叙事偏好：视角、节奏、悬念强度等。
- 创作边界：用户明确不希望出现的题材、尺度和结局。

### Agent 内部需要保留的信息

每个结果至少需要记录：

- 当前结论。
- 结论来源于哪一段对话或哪一次选择。
- Agent 对结论的判断置信度。
- 该结论是否经过用户明确确认。

### 完成判断

- 结果可以来自直接回答，也可以由 Agent 从多个回答中推断。
- 关键结果缺失或置信度不足时，Agent 应换一种更有趣的方式追问。
- 关键结果覆盖充分后，才允许整理为故事设定。
- 探索问题数量由理解充分程度决定，而不是由固定轮数决定。
- 用户在右侧直接修改或明确确认某项设定后，应提高该结果的确定性，并避免重复提问。

### 当前原型差距

当前原型以固定问答轮数开启“整理为故事设定”，尚未实现结果覆盖度、证据来源、置信度和确认状态的判断。

## 后续记录规则

后续探索页面无法直接体现在原型中的新需求按以下方式维护：

1. 在“需求概览”中新增编号、标题、状态和记录日期。
2. 在正文新增对应章节，写清目标、交互规则、当前原型差距和仍待讨论的问题。
3. 如果需求后来可以直接通过原型表达，则从本文档移除，并把稳定规则同步到 [原型规格](prototype-spec.md)。
4. 尚未确认的机制性想法应明确标记为“待设计”，不能写成已经落地的规则。
