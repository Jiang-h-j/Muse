## 2026-07-23 · UX 文档反向蒸馏（原型 → BMAD spine）

**触发**：Muse 走 BMAD 规划流程，但 UX 一直以"前端原型 + prototype-spec.md"承载，无 BMAD 规范的 UX 交付物（`DESIGN.md`/`EXPERIENCE.md`）。实现就绪校验时发现此缺口，创始人 Jianghj 要求"按 BMAD 规范补一份，放到对应位置"。

**核心冲突与裁决**：
- BMAD-UX 默认规则是"两份 spine（DESIGN/EXPERIENCE）win on conflict with any mock, wireframe, or import"——设计文档凌驾原型。
- Muse 铁律相反："原型（`prototype/app/`）= 契约的最终事实基准"，architecture.md 与 epics.md 均已把原型钉为 inputDocuments 事实源。
- **裁决（用户选"从原型反向蒸馏"）**：产出 BMAD 规范形态的 `DESIGN.md` + `EXPERIENCE.md`，但内容 100% 从原型代码反向提取，并在两份文件的 `authority_note` 与正文顶部显式声明"本文件服从原型、不凌驾"。既补齐 BMAD 交付物，又不违反"原型=事实基准"铁律，也不推翻已建立的 architecture/epics 事实链。

**方法**：派两个只读子 agent 并行通读原型（styles.css 3901 行、app.js 1905 行 + spec），分别提取视觉事实与交互事实，主上下文据此组装两份 spine。token 值照抄原文、标源行号。

**蒸馏中发现、已在文档标注的事实**：
1. **存储纠偏**：原型用 `sessionStorage`（会话级），非 architecture/任务描述里说的 localStorage——决定"待确认设定刷新不丢、关标签页清空"。
2. **登录 error 态是预览态**：expired/invalid/locked 仅能经页内 state-preview 手动触发，非真实校验产生。
3. **缺陷 token**：`--sans`（styles.css:2991）、`--line-soft`（styles.css:3480）被引用但 `:root` 未定义，会静默回退——已在 DESIGN.md 标"待补"。
4. **无深色模式 / 无间距·圆角·阴影 scale token**：除颜色字体外均硬编码字面量。
5. **两处文案/路由小不一致**：章节页返回链接写"← 阶段规划"实指向 explore；作品库非 nameless 作品点"继续"显示"目标页面待设计"占位。

**PRD 归位（同期决策，用户选"暂不动"）**：根目录 `Muse-PRD-V1.md` 三件套未迁到 BMAD 规范路径 `prds/prd-Muse-.../`，因 architecture/epics 已引用其根目录路径为 inputDocuments，迁移会打断事实链。仅在实现就绪报告记录"PRD 位置偏离规范"。

**未纳入 spine 的项（待其实现时补入）**：EXP-P01/P02（动态选题、覆盖度判断，epics 归 V2）、UX-DR1（文风样本锚点入口）、UX-DR2（BYOK 设置页 + 用量入口）——原型均未表达，版本归属以 epics.md 为准。

**状态**：DESIGN.md / EXPERIENCE.md 均 `status: draft`。未跑 BMAD-UX Reviewer Gate（可选、成本高）；如需正式定稿再走 Validate。
