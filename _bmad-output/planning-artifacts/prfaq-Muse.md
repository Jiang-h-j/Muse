# 你读了几百本小说。现在，轮到你写一本了。

## Muse 是一个 AI 创作伙伴，陪那些心里一直有个故事、却觉得自己写不出来的读者，把它一章章写出来——署上你自己的名字。

**中国，2026 年 —— Muse 今日正式发布。你有没有过这样的时刻：读到入神时，脑子里会自己冒出一段别人没写的剧情、一个你更想看到的走向？对几百万爱读小说的人来说，这个念头几秒钟就散了，从没被当成「我也能写」的信号。Muse 是一个 AI 创作伙伴，它接住这个念头——陪你把心里那个一直没敢写的故事，一章章写成一部署着你名字的作品。**

你比谁都懂一个好故事该是什么样子——你读了那么多，一眼就能看出哪里写崩了、哪个人物立住了。你甚至常常在脑子里，替某个角色走了另一条路。可每次那个「我也想写」的念头刚冒头，同一个声音就把它按了回去：我又不是作家，我连第一句怎么开头都不知道。于是你合上书，那个只属于你的故事，又一次沉回心底，像从没存在过。

有了 Muse，你不再需要一个人对着空白页。它先陪你聊——不是逼你想清楚整个故事，而是从你脑子里那些零碎的画面、说不清的偏好开始，一点点把「我也说不上来想写什么」变成一个真正立得住的故事雏形。然后你们一章接一章往下写：每一章你都先看到它写出来的样子，不满意就告诉它哪里不对，它改；满意了就定下来，成为下一章的基石。你始终握着方向盘——设定是你选的，走向是你定的，每一次修改都是你的决定。写到最后，你手里是一部完整的小说——一部你可以署上自己名字、拿给别人读的小说。它不会说这是它写的，因为这确实是你写的。

> "我们不是要造一台小说机器。市面上不缺能一键生成故事的工具——但读者要的从来不是『一个故事』，而是『**我的**那个故事』。Muse 存在的意义，是让每一个曾经以为自己只能当读者的人发现：那条线，本来就不存在。"
> —— {待定}，Muse 创始人

### How It Works

**1. 从一个念头开始。** 你不用想好整个故事。Muse 问你几个问题——不是「你要写什么类型」，而是从画面和感觉入手：此刻你脑中最先亮起来的，是一个人、一个场景，还是一种情绪？你只管选，或者用一句话说说。

**2. 看着模糊变清晰。** 聊着聊着，那些说不清的偏好被整理成一份故事设定：主角是谁、世界什么样、核心冲突在哪。你可以随时改，直到它真的像「你的」故事。

**3. 一章一章地写。** 确认设定后，Muse 陪你写第一章。你先读它写出来的样子，在段落上标注、告诉它哪里不对，它据此改；满意了，这一章就定稿，成为下一章的基石。

**4. 拥有它，也可以分享它。** 写到哪都存着。你可以把完成的作品放上自己的作品页，署上名字，让朋友、让别人读到——并听到他们的回应。

> "我一直以为写小说是作家的事。用 Muse 的第二天晚上，我把写好的第一章发给我老婆，她回了句『这后面呢？我想看』。那一刻我愣了一下——我这辈子第一次，写了个有人想追的东西。"
> —— 阿哲，32 岁，某互联网公司产品经理，读了十几年小说

### Getting Started

Muse 现已开放。用邮箱注册，凭邀请码进入。从你的第一个念头到写下第一章，通常只需要一个晚上。不需要任何写作经验——你需要的，只是曾经读过、并且悄悄想过「要是我来写会怎样」。

## Customer FAQ

### Q: 一个大部分文字由 AI 生成的故事，凭什么算我「写的」？拿给别人看不心虚吗？

A: 文字是 AI 落的，但**决定这个故事成为这个故事的每一个选择，是你做的**——主角是谁、他要什么、故事往哪拐、哪一版你不满意要重来。AI 是你的写手，你是拿主意的那个人。

而且 Muse 从不把你锁在选项里：每个选择旁你都能用自己的话另起一句；不想被引导时，直接进自由探索模式，和 AI 从头发散地聊出你自己的东西。给你选项，只是因为很多人有冲动却一时脑子空白，需要一个起步的台阶——**台阶随时能迈开，方向盘一直在你手里**。所以它不是「AI 写的你选了选」，是「你定的故事，AI 帮你落成字」。这经得起你拿给任何人看。

### Q: 你说一个晚上就能写出第一章。可出来的东西是真能读、有我的味道，还是 AI 那种一眼假、翻译腔的正确废话？我读了十几年小说，眼光很刁。

A: 这是我们的红线，不是可以慢慢优化的事——因为我们的用户恰恰是眼光最刁的人，糊弄不了。所以「读起来不像 AI」被当作**上线的硬门槛**：在你开始设定故事时，Muse 会让你锚定一个你爱读的文风，之后每一章的产出都贴着那个味道来写，而不是吐给你一段四平八稳的通用 AI 腔。负责写作的 Agent 专门挂了写作与「去 AI 味」的能力，产出与你选定风格的贴合度达不到标准，就不算合格。**衡量好坏的尺子，是「像不像你想要的味道」，不是「像不像 AI」。**

### Q: 就算我写完了，然后呢？放在作品页上会有人看吗，还是只有身边人捧场点个赞？没人看，我图什么？

A: 你不用把作品扔进职业网文平台那种红海里——一个刚起步的人，把第一部作品丢进日更万字、评论区互相厮杀的地方，只会被沉底。Muse 里是另一种地方：**一个全是「读者转作者」的新手圈子，每个人都是刚起步的同路人，基调是「我想看你后面怎么写」而不是打分排名。** 你会拥有熟人以外、但同样善意的第一批陌生读者。我们刻意不做全站热榜、不请职业作者来降维打击——因为这里要保护的，是你敢把第一部作品拿出来的那点勇气。至于把成品带去更大的平台，那是你以后有底气了自己的选择，Muse 不催你、也不替你决定。

### Q: 我连三行都写不完，写一整本书听着像个几个月的大工程——我怎么知道自己不会又一次半途而废、然后更确信「我果然不行」？

A: Muse 不要求你「写一本书」，只要求你写**下一章**。你永远只面对眼前这一章：先看到它的样子、改到你满意、定稿——一次一小步的成就感，而不是一座望不到头的山。中途停下也没有「烂尾」的判决，存着的进度一直在，什么时候想回来都行。**我们把「写一本书」这件大事，拆成了你每次只需要点头的一小步。**

### Q: 这不就是 ChatGPT 换个皮吗？我自己让 ChatGPT 写一章，它当场也给我。

A: ChatGPT 会**替你把故事定了**——你说个模糊想法，它直接给你一整章，人物、走向都是它替你选的，你成了旁观者。Muse 反过来：它不替你定故事，而是**帮你把你自己都说不清的想法逼出来、变成你的**，再一章章落成你选定的样子。ChatGPT 给你「一个故事」；Muse 让你得到「**我的**那个故事」。差别不在谁会写字，在**谁做主**。

### Q: 我脑子里的故事是我最私密的东西。我写的内容你们拿去干嘛？会拿去训练模型吗？版权到底归谁？

A: 【待定 — 需用户决定】你的作品归你、版权是你的，我们不拿你的私密创作去训练模型。*（占位表述；数据使用政策、是否用于训练、版权归属条款为法律+商业承诺，需创始人正式拍板后据实填写，不可用营销话术糊弄。）*

### Q: 现在 AI 产品一茬一茬地死。我投入几十个小时写了半本，你们哪天关门了，我的作品跟着陪葬吗？

A: 你的作品**随时可以完整导出带走**（标准格式）——它存在我们这，但从不锁在我们手里。就算哪天 Muse 不在了，你写下的东西还是你的。*（注：导出用于数据主权与「逃生舱」，与「不主动引流用户去外部竞技平台」不冲突——一个是用户随时可行使的权利，一个是产品不推的动作。）*

### Q: 到底怎么收费？写一本书要花我多少钱？

A: 【待定 — 需用户决定】*（商业模式尚未确定：订阅制 / 免费写+增值 / 按用量等均未定。占位，待创始人决策后填写。避免「写着写着弹付费墙」这类伤害信任的设计。）*

## 概念核心（Stage 1 敲定）

| 要素 | 内容 |
|---|---|
| **客户** | 爱读不爱写、偶尔幻想「要是我来写会怎样」的重度小说读者 |
| **问题** | 心里其实有故事（脑内常驻画面），却从没觉得自己「能写」、也没有出口把它外化 |
| **stakes** | **身份兑现**——从终身「读者」跃迁为能指着作品说「这是我写的」的创作者 |
| **方案** | AI 陪他把一个模糊想法一章章写成**完全属于自己**的原创小说；用户全程掌握设定/选择/修改权 |
| **概念类型** | 商业产品（commercial） |

**关键战略：漏斗结构。** ①「把你读到的烂尾帮你重写」= 获客钩子（营销入口，冲动最猛最精准，但不进产品核心、不做成同人工具）；④「挖出你心里本就有的故事」= 产品内核（留存 + 品牌）。

**产品性质定性：** 目标用户**无痛**（不写也照常过日子），因此 Muse 是「创造需求 / 点火 + 即时满足」型产品（类比 TikTok 让不拍视频的人开始拍），非止痛药型。成功变量 = 点燃冲动 + 在热情冷却前即时兑现成果。

### Q1（技术最硬处：跨章长程一致性）
写到第 8、10 章时人物性格/已发生事件/伏笔不能崩，这是当前 LLM 最难点（上下文窗口+状态管理）。「分阶段归档/设定圣经」是拟解法——但在第 10 章还扛得住吗？是「知道怎么建」还是「赌它能成」？

**答案：** 从"赌"转为**"知道怎么建"**——决策 = **直接采用 webnovel-writer 的 Story System 一致性机制**（该项目已开源跑通、Trendshift 上榜，且此部分与网文题材无关，是长篇原创刚需）。机制闭环：
1. **写前** context-agent 把「设定圣经(story_contracts) + 最近章节摘要 + 未回收伏笔(urgent_loops) + 世界规则 + 主角状态」压成写作任务书喂给生成；
2. **写后** data-agent 从正文提取事件/状态变化/新增实体 → 结构化 JSON → 一次 chapter-commit 投影回 state/index/summary/memory/vector；
3. **RAG** BM25+向量+rerank 三级检索按相关性召回历史设定/情节，可选增强，无 key 退回 BM25。
   → 这即 PRD 模块2（设定圣经）+ 模块4（章节卡片/归档）想要的能力，且更细、带审计日志与断点续跑。

**边界与清醒认知（已与用户确认）：**
- **(a) 机制照搬、章数不设人为上限**：原样采用其为"几百章"设计的机制，**实现时不得人为砍成 20–50 章**。20–50 章只是"文学向用户单本大致长度"的**参照系**（用来判断该机制在 Muse 场景够用），**不是产品硬上限**。用户认为这套机制够用。
- **(b) 借思路 + 借部分代码，非装上即用**（用户已认）：webnovel-writer 是 Python + 跑在 Claude Code 内的单机单书 skill 框架、以文件系统当库；Muse 是多用户 Web 产品，**存储层/调度需为多用户后端重写**，此工作量 PRD 未计入。
- **(c) 残留风险绕回 Q2**：一致性依赖 data-agent「读正文提取新事实」，此提取环节仍由 LLM(DeepSeek) 完成——提取漏/错则后续穿帮。故 Q1 的可靠性上限受 Q2（DeepSeek 质量）牵制，非独立可保。

### Q2（红线撞车，最尖锐 ★生死题）
Stage 3 立了死命令：产出不能有 AI 味否则不上线。但 DeepSeek 的中文网文腔恰是其典型短板——上线拦路石架在了已知有此短板的模型上。「去 AI 味 skill」能否把 DeepSeek 救到骗过刁钻读者？**测过没有，还是纸上谈兵？** 救不动时：换模型(成本飙升、单位经济崩)还是降红线(打脸 Stage 3)？

**答案：** 决策 = **A2 坚持用 DeepSeek 起草正文，暂不做验证测试**。诚实定性：这是**未验证的头号生死假设**——"DeepSeek 在去 AI 味规则约束下能否产出过刁钻读者红线的文字"目前是赌，不是知。

- **参照系（新增，来自开源项目 webnovel-writer 调研）**：该项目已证明"长篇一致性框架 + Anti-AI 词表规则 = 质量达标（Trendshift 上榜、真实连载到几百章）"，**但它的正文实际由宿主 Claude 生成，不是 DeepSeek**；代码里没有任何正文生成的 API 接入层，写作智能寄生在 Claude 上。它的"去 AI 味"是一份 `polish-guide.md`（200+ 词黑名单 + 7 层句式规则）让模型**自查自改**，连词频都非硬门槛——是软机制，可靠性取决于底层模型够不够老实、有没有文笔。
- **因此风险收窄为单一问题**：同一套任务书 + 同一份去 AI 味词表，把生成模型从 Claude 换成 DeepSeek，质量掉多少、过不过红线？**未测。**
- **缓解**：直接复用 webnovel-writer 的 `polish-guide` 词表规则 + Story System 一致性骨架（降低自研风险）；正文生成接入层与"锚定用户爱读文风"机制需自建（该项目均无，且其文风控制是网文套路化，与 Muse 文学向相反）。
- **钉死的验证时点**：最晚在为「模块3·创作」写正文生成接入、或任何真实用户试读之前，必须完成 "Claude vs DeepSeek 同任务书盲读对比"。在此之前 Muse 核心可行性 = **路线已定、及格线未验证**。
- **红线定义澄清（回答 Stage 3 的 launch blocker）**：维持"必须过最低可留存门槛"——门槛线具体划在哪，待上述对比测试确定；不接受无限期"慢慢提升"。

### Q3（一人全栈的能力缺口：内容审核）
已承诺创作闭环 + 中档+社交(作品页/点赞评论/新手发现/内容审核)。Claude Code 能写前端和 CRUD，但内容审核(UGC 公开后涉黄涉政必须处理，否则平台被封)是运营+合规活，非写代码可绕过。一个人这块怎么扛？

**答案：** **V1 已规避（由 Q9-B 降级）。** 熟人只读链接分享不构成公开 UGC 广场，无需平台级涉黄涉政巡查体系；审核责任降至"熟人可见内容"，低一个数量级。**V2 引入站内公开社区前，这是必须先解决的前置条件**（届时需要审核方案或第三方审核 API），不再是 V1 生死题。

### Q4（单位经济）
用户「一晚写一章」且反复重写。DeepSeek 便宜，但一个重度用户每月烧多少 API 钱？定价(Q8)还没想好——怎么保证不是每多一个活跃用户就多亏一份钱？免费期能烧多久？

**答案：** 决策 = **Q4-B 托管为主 + BYOK 进阶**（用户已选）。
- **默认：平台托管**（Muse 的 Key，用户无感、零门槛进来即写）→ 保住发布稿"一个晚上、不需经验"的承诺；**成本护栏 = 给托管设免费额度上限**（如 N 章/天或 N 次生成/天），顶住烧钱。
- **进阶：BYOK**（用户在设置页绑定自己的 API Key，成本自付）→ 给重度用户解绑额度，**正好把最烧钱的重度用户成本挪走**，缓解单人现金流。
- **成本结构提醒（来自 Q1 机制）**：写一章非单次调用，是 context-agent 拉取 + 起草 + reviewer 审查 + 去 AI 味润色 + data-agent 提取的**多次调用叠加**，叠加用户反复重写 → 单章真实 token 成本需按"5–10 次调用/章"量级估。**用户尚未精算，属可接受未知**。
- **换模型后门的成本尾巴（承接 Q7）**：BYOK 下换 Claude = 用户自绑 Key 自付高价；托管下换贵模型 = Muse 成本上升，须重算额度线。
- **V1 必答小尾巴**：托管免费额度的具体数值（几章/天）需在实现前定，取决于 Q2 盲测出的"单章真实成本"。
- **待定**：正式定价/商业模式仍未定（见 Q8 商业模式占位），BYOK 只解决"不为每个活跃用户净亏"，不等于盈利模式。

### Q5（冷启动，头号业务难题）
用户是无痛人群(不主动上门) + 要建社区(冷启动最难品类，没人则空城)。无营销预算的独立开发者，前 100 个真实创作者从哪来？「发小红书/朋友圈」够不够填满新手社区？

**答案：** **V1 已规避（由 Q9-B 降级）。** V1 不做社区，无"填满广场"的冷启动压力；增长回归最朴素路径——单个用户来写、写完生成只读链接自己分享，分享链接本身自带熟人拉新口子（被分享者可能也想写）。**"社区冷启动"作为 V2 引入公开社区时的头号业务难题保留**，届时再正面回答"前 100 个创作者从哪来"。

### Q6（护城河）
DeepSeek 谁都能调，探索流程可被抄，番茄/阅文有钱有流量有模型。一个人凭什么守得住？Muse 真正抄不走的是什么？

**答案：** 诚实定性——**单人阶段几乎无传统技术护城河**（模型调 DeepSeek 人人可调；一致性机制抄开源 GPL 项目人人可抄；探索/创作流程是产品设计可复刻）。故不硬造技术壁垒，采用 **护城河一 + 二 组合**（用户已选）：
- **一 · 定位卡位 + 心智**：「纯读者→创作者」定位目前**无人占领**（Sudowrite/番茄/阅文全预设"用户本来就想写"）。大厂不做非不会做，是**看不上**——该人群无痛、变现不明、与其网文主业逻辑相反。护城河 = **大厂战略盲区 + 先占住这群人心智**。
- **二 · 不争大厂，赌细分小市场**：单人项目服务好一小群"读者转作者"，活成**小而美、能自养**即赢，不需"守得住"。
- **必须记住的尾部风险（写入 verdict）**：护城河一的前提是"大厂盲区"——**一旦"读者→创作者"被验证有利可图，盲区消失，大厂可携流量/模型/资金下场**。Muse 无技术壁垒抵挡，届时只能靠先发心智 + 用户创作数据沉淀（护城河三，V1 未采用但可作 V2 加固方向）。此为战略上限，非 V1 生死题。

### Q7（什么会杀死它 ★生死题）
若 DeepSeek 救不出满意的文字质量，整个产品是否就不成立？这是不是唯一的、一票否决的生死变量？

**答案：** 等式"DeepSeek 质量 = Muse 生死"**不成立**，理由三层（用户已确认）：
1. **生死变量是"文字质量本身，不绑死 DeepSeek"**：DeepSeek 是**首选而非唯一**，救不动可换模型（Q2 的 A2 留换模型后门）。故变量是"质量能否达线"，不是"某个模型行不行"。
2. **红线是行为线，不是"骗过刁钻读者"**（第二次下修 Stage 3 红线，就此钉死可操作判据）：
   - 不及格 = 用户读两段觉得"AI 糊的"，不想改也不想往下写；
   - **及格线（launch blocker 画在此）= 用户读完第一章觉得"像那么回事、有些想改，但愿意改、愿意写下一章"，且文字"拿得出手、愿意分享给熟人"**；
   - 理想（V2）= 骗过刁钻读者、有文学质感。
3. **价值部分在过程与身份兑现**：Muse 价值有一部分在"全程用户做主"的参与感（理由三），可补偿文字非顶级 B+。
- **但仍是 launch blocker**：文字若连"愿意写下一章 / 拿得出手分享给熟人"都做不到，产品不成立——因 Q9-B 的身份兑现闭环靠"分享作品听到回响"，前提是拿得出手。这条更低但明确的线，仍需 Q2 的 Claude-vs-DeepSeek 盲读测试验证 DeepSeek 够不够得着。
- **换模型后门的代价**：Q4 成本估算须纳入"可能需换贵模型"的尾部风险。

### Q8（法律敞口，一人扛不起的那个）
用户在平台公开发布作品。有人用产品写违法内容并发布，责任在平台；中国 2025.9.1 起 AI 内容强制标识是硬法规。一个自然人开发者担得起 UGC+AI 平台的合规责任吗？(可能意味着需要的不是更多代码，而是一个主体资质)

**答案：** **V1 大幅退场（由 Q9-B 降级）。** 无公开发布平台 → 自然人扛不起的"UGC+AI 平台合规主体资质"问题 V1 阶段退场。**仍在的义务**：2025.9.1 起 AI 生成内容强制标识——这是对生成内容本身的标注义务，须在 V1 落实（导出件/分享页标注 AI 辅助生成），但属"加标识"而非"建平台审核体系"。**V2 引入公开社区/发布平台前，主体资质与平台责任必须重新评估**（可能需要公司主体而非自然人）。

### Q9（创始人不敢说出口的那个 ★生死题）
有没有可能其实不需要做社区、不需要做那么大？为解决 Q4(留存)一路加到「中档+社区」，而社区正是把 Q3/Q5/Q8 难度乘以十的东西。若去掉社区，Muse 作为纯粹的「私人创作工具」能不能先活下来？是真的需要社区，还是被 PRFAQ 逻辑推着停不下来了？

**答案：** 决策 = **Q9-B 轻分享，不做社区**。V1 = 写完 + 导出 + **生成只读分享链接给熟人**（满足"给人看、听到回响"的身份兑现最小闭环，如 PRFAQ 中阿哲把第一章发给老婆的例子）；**站内公开社区、点赞评论、新手发现整体推到 V2 及以后**。
- **stake 未落空**：身份兑现（读者→"这是我写的"）靠"熟人只读分享"兑现，不必等公开社区。分享 ≠ 社区。
- **下修既有决策（需收尾时同步三处）**：Stage 2/Stage 3 定的"中档+社交（作品页+熟人可读+点赞评论+站内新手发现，路线图硬承诺）"**下修**为上述 V1 轻分享。待办同步：① 记忆 `project-muse-social-scope`；② PRD-V1 模块5"通读与交付"及涉社交处；③ 本文件 Stage 2/Stage 3 注释的"中档+"表述。
- **连锁收益**：Q3/Q5/Q8 在 V1 范围内由"生死题"降级为"V2 引入公开社区前的前置条件"（见各题）。

## The Verdict（Stage 5 — 综合裁决）

### 一句话裁决
**Muse 是一个战略上已想清楚、可以启动 V1 的概念——但它的成立与否押在唯一一个尚未验证的假设上：DeepSeek（或替代模型）在去 AI 味规则约束下，能否产出让目标读者"愿意写下一章、且拿得出手分享给熟人"的文字。** 这个假设验证成本极低（半天盲读对比），却被推迟；在验证之前，Muse 的核心可行性等级是 **"路线已定、及格线未验证"**。

### 概念强度评估

| 维度 | 评级 | 依据 |
|---|---|---|
| **客户与问题清晰度** | 强 | "爱读不爱写、幻想过自己写"的读者，画像具体；stake=身份兑现，锋利 |
| **差异化定位** | 强 | "纯读者→创作者"是无人占领的蓝海（竞品全预设用户本来就想写） |
| **技术可行性 · 一致性** | 中强 | 有开源方案（webnovel-writer）趟平并可迁移，从赌变知道怎么建 |
| **技术可行性 · 文字质量** | ⚠ 未验证（最高风险） | DeepSeek 去 AI 味未测；这是唯一悬空的 launch blocker |
| **范围收敛度** | 强 | Q9-B 砍社区，V1 收敛为"写完+导出+熟人轻分享"，砍掉三座合规/运营大山 |
| **单位经济** | 中 | Q4-B 托管+BYOK 结构性缓解，但单章成本未精算、定价未定 |
| **护城河** | 弱（可接受） | 无技术壁垒，靠大厂盲区+小而美；单人阶段诚实且够用 |
| **商业模式** | ⚠ 未定 | 定价、数据/版权政策仍占位待创始人拍板 |

### 三个必须带着走的真相（Go 但睁眼）
1. **文字质量是唯一没兜底的生死变量**——先做那个半天盲读测试，再写模块3 的生成接入代码。这是全项目性价比最高的一次去风险。
2. **借开源是"借骨架+词表"，不是"装上即用"**——一致性机制与去AI味词表可迁移，但模型接入层、文风样本锚定、多用户Web存储层都要自建，这部分工作量 PRD 未计入。
3. **两处硬缺口不能用营销话术糊弄**——数据/版权政策、商业模式定价，属法律+商业承诺，须创始人正式拍板。

### 裁决：**GO（附条件）**
概念够扎实、范围够收敛、风险够清晰，可以进入 PRD 精修 → 架构 → 开发。**附带条件 = 上述真相1的盲读测试必须在生成接入开发前完成**。若测试证明 DeepSeek 连行为红线都够不着且换模型使 Q4 经济崩溃，则回到 Correct Course 重估——但这是小概率尾部，不是当前主路径。

1. 同步收尾（记忆 + PRD-V1 按 Q9-B / Q4-B / Q7 红线校准）；
2. 进入 PRD 精修（`bmad-prd`），把 PRFAQ 的决策与红线灌入 PRD-V1；
3. 架构（`bmad-create-architecture`），重点设计：模型接入层、文风样本锚定、多用户存储层、webnovel-writer 一致性机制的迁移。
