# Sprint Change Proposal — 自由探索从无限追问转为系统主导补齐设定

- **日期：** 2026-07-31
- **作者：** Jianghj（Correct Course，Incremental 模式）
- **变更规模：** Moderate
- **推荐路径：** Direct Adjustment（新增 Story 2.8 + 改写进行中的 Story 7.6 + 提前 EXP-P02 最小能力）
- **提案状态：** 待最终批准；批准前不修改 Epic、架构、Sprint 状态或实现代码

---

## 1. 问题摘要

### 触发

Story 7.6 接入真实自由探索 Agent 后，实际浏览器体验暴露出三个问题：

1. “给我一些讨论方向”看起来像 AI 根据当前上下文提供帮助，实际只是前端固定的三句文本；
2. Agent 只会沿着用户当前话题继续追问，没有判断“设定还缺什么、何时换方向、何时停止”的职责，容易围绕单一方向无限问下去；
3. 当前自由探索只需一条用户消息就能整理设定，无法保证设定卡所需的主干信息已经形成。

### 问题定性

这是**原需求对 Agent 主导程度和探索完成条件定义不足**，不是单纯文案问题，也不是现有 SSE 接线的技术故障。它同时影响自由探索的用户旅程、后端 Agent 契约、整理门禁和候选设定卡质量。

### 代码与文档证据

- `backend/src/muse/services/free_explorer_agent.py:41-56` 要求 Agent 顺着用户话头、一次只问一个问题，但没有主干字段覆盖、换题或收束规则；
- `free_explorer_agent.py:58-64` 与 `story_clue.py:54-66` 只有 4 个 preset 线索，无法表达 7 个通用主干字段；
- `exploration_service.trigger_free_settle` 仅检查是否存在一条 free user message；
- `prototype/spec/exploration-pending-requirements.md` 的 EXP-P02 已描述“按设定结果覆盖度决定探索是否完成”，但此前被放到 V2；
- `prfaq-Muse.md:54,142` 明确“选项是脚手架、方向盘在用户手里”。本变更与该原则一致：系统负责发现缺项和收束，用户负责故事答案并保有改写权。

## 2. 已确认的产品裁定

| 决策 | 规则 |
|---|---|
| 整理门槛 | 题材、核心吸引力、主角、主要冲突、关键世界规则、整体气质、开篇钩子 7 项主干均为 `filled` 或 `skipped` 后，才开放整理。题材特化字段与文风锚点不阻塞。 |
| 跳过 | 用户点“先跳过”后，系统不再反复追问该项；根据已有材料谨慎归纳并标记 `skipped`，用户之后仍可在候选卡修改。 |
| AI 回答思路 | 仅在用户点“没想好？看看几个思路”时按需生成 2–4 个当前问题相关选项，不在每轮自动生成。 |
| 点击选项 | 点击某个 AI 回答思路后，直接作为本轮回答提交，立即更新完成度并推进下一项。 |
| 零对话状态 | 展示“你想从哪里开始？”四个产品入口：故事想法、主角、核心冲突、世界与氛围；它们不是 AI 建议。 |
| 页面流 | 采用“自由入口 → 对话内具体问题 → 按需思路或跳过 → 7 项完成后明确收束”的流程；继续保留左对话、右 Living notes 双栏。 |
| 用户主导权 | 始终允许用户自行输入；右侧线索可直接编辑且用户编辑优先；候选卡仍可继续修改。 |

## 4. 推荐方案

### 4.1 方案对比

| 方案 | 结论 | 工作量 | 风险 |
|---|---|---:|---:|
| Option 1：直接调整现有 Epic/Story | **采纳** | 中 | 中 |
| Option 2：回滚 2.6/2.7 与 7.6 | 否决；真实聊天、SSE、线索与清理基础仍有价值 | 高 | 高 |
| Option 3：缩减 MVP，仅改文案/提示 | 否决；无法解决无限追问与过早整理根因 | 低 | 高 |
| 新建独立 Epic | 否决；能力仍属于探索闭环，拆出会放大计划复杂度 | 高 | 中 |

### 4.2 推荐理由

- 最大化复用现有后端聊天/线索与 7.6 SSE 接线；
- 把原先错误推迟到 V2、但实际为 V1 收束必需的 EXP-P02 最小能力提前；
- 不引入完整置信度、证据链、问题原型库等重型机制，控制 MVP 工作量；
- 直接提高 7.7 候选卡质量，并避免在错误自由探索体验上继续开发。

### 4.3 范围分类

**Moderate。** 需要新增一个后端 Story、改写一个进行中前端 Story并同步规划/架构工件；不需要 PM 级重做 PRD，也不需要新 Epic 或技术栈变更。

## 5. 详细变更提案

### 5.1 FR9

**OLD（摘要）：**

> 自由探索连续对话；右侧线索可编辑；“给我一些方向”只把固定选择写入输入框。

**NEW：**

> 用户可从故事想法、主角、核心冲突、世界与氛围任一入口开始自由探索。系统依据已有材料主导补齐设定主干缺项，每轮只提出一个具体问题；用户可自行输入，卡住时按需查看 AI 生成的 2–4 个回答思路并直接选择，也可跳过当前项。Agent 不替用户决定故事；右侧线索可直接编辑且用户编辑优先，不被自动整理覆盖。

### 5.2 FR10

**OLD（摘要）：**

> 至少一条用户消息并主动点击后即可整理。

**NEW：**

> 仅当题材、核心吸引力、主角、主要冲突、关键世界规则、整体气质、开篇钩子均已补齐，或经用户跳过后由系统依据已有材料谨慎归纳，且用户主动点击时，才允许整理为故事设定。题材特化字段和文风锚点不阻塞。

### 5.3 UX-DR5

**删除：** “给我一些讨论方向”会话级复选框与三个固定文本选项。

**新增五态：**

1. 零对话：`你想从哪里开始？` 四个固定产品入口；
2. 进行中：最新 Agent 轮次下显示一个当前具体问题；
3. 卡住帮助：`没想好？看看几个思路`，按需请求 2–4 个 AI 选项；
4. 跳过：`先跳过这个问题`，标记当前项 `skipped` 并推进；
5. 完成：Agent 明确提示“故事骨架已经够清楚”，停止继续抛问题并开放整理。

**保留：** 连续只读对话、自动滚底、右侧线索直接编辑、用户编辑优先、用户主动点击整理。

### 5.4 新增 Story 2.8

**标题：** 自由探索——设定导航、按需回答思路与 7 项完成度门禁

**核心 AC：**

1. 为 7 个通用主干维护 `missing / filled / skipped` 状态；
2. 每轮根据对话与线索更新覆盖状态，只选择一个最需补齐项并生成下一问；
3. 同一项达到 `filled` 或用户标记 `skipped` 后，不继续围绕它重复追问；
4. 零对话时接收四个起点之一，生成对应第一问；
5. 按需生成当前问题的 2–4 个回答思路；
6. 用户跳过后转下一项，系统只基于已有材料谨慎归纳；
7. 7 项均为 `filled/skipped` 才返回 `readyToSettle=true`；free settle 后端硬校验该状态；
8. 保持租户/mode 守卫、camelCase 边界、Provider 记账与 `story_clue.user_edited` 保护；
9. 题材特化字段和文风锚点不参与完成门禁；
10. 导航状态刷新可恢复，不依赖前端 sessionStorage 作为业务真相源。

### 5.5 Story 7.6 改写

**标题改为：**

> 自由探索接线（系统引导 / 按需回答思路 / 线索编辑持久化 / 7项完成度门禁）

**保留现有实现：**

- `apiStream`、Bearer/401、AbortController；
- 自由消息真实 SSE 与持久化恢复；
- 右侧 preset/custom 线索 CRUD 与 `userEdited` 保护；
- 跨项目/跨账号的加载代次与流清理；
- free settle task SSE 与候选卡弹出。

**替换：**

- 固定方向复选框/三句文本 → 零对话四入口 + 当前问题下按需 AI 思路；
- 基于一条 user message 的门禁 → 基于后端 `readyToSettle`；
- 单纯顺话题聊天 → 消费 guidance 的当前字段、当前问题与收束态；
- 新增跳过操作、选项直接提交、刷新恢复 guidance。

### 5.6 Architecture

建议在 `exploration_session` 增加窄范围持久状态，如 `guidance_state JSONB`，至少包含：

```json
{
  "fields": {
    "genre": "filled",
    "coreAppeal": "missing",
    "protagonist": "skipped",
    "mainConflict": "filled",
    "worldRules": "filled",
    "overallTone": "filled",
    "openingHook": "missing"
  },
  "currentField": "coreAppeal",
  "currentQuestion": "读者最想从这个故事里获得什么感觉？",
  "readyToSettle": false
}
```

约束：

- `story_clue` 继续作为用户可编辑 Living notes，不与 guidance 合表；
- guidance 是完成度与下一问的后端事实源；
- 不在 V1 保存完整置信度、证据来源和问题历史；
- guidance API 仍走 router → service → repository、租户/mode 守卫、Pydantic camelCase；
- 结构化判断与建议生成一律经 `LLMProvider`，不得直调 SDK。

建议能力边界：

- `GET /free/guidance`：恢复完成度、当前问题、收束态；
- `POST /free/guidance/start`：从四个起点生成第一问；
- `POST /free/guidance/refresh`：每轮更新线索、覆盖度和下一问；
- `POST /free/guidance/suggestions`：按需生成当前问题选项；
- `POST /free/guidance/skip`：跳过当前项并推进；
- `POST /free/settle`：改为校验 7 项 guidance 状态。

具体路径可在 Story 2.8 技术设计时小幅调整，但职责和事实边界不得改变。

### 5.7 EXP-P01 / EXP-P02

- **EXP-P02：** 最小能力提前到 V1 Story 2.8：7 项状态、单项下一问、跳过、后端门禁；完整的来源追溯、置信度、用户确认状态和多角度交叉验证仍留 V2。
- **EXP-P01：** 完整问题原型库、推断标签和动态选题仍留 V2；V1 只让 Agent 围绕当前缺项产生一个具体问题，零对话四入口为固定产品入口。

### 5.8 Sprint Status

批准后新增：

```yaml
2-8-自由探索设定导航按需回答思路7项完成度门禁: backlog
```

Story 7.6 保持 `in-progress`；更新标题 key 需同步 story 文件名与 sprint-status key。7.7 保持 `backlog`。

## 6. 实施交接

### 交接对象

- **PO / Developer：** 更新 `epics.md`、`architecture.md`、`exploration-pending-requirements.md`、Story 7.6 与 `sprint-status.yaml`；
- **Developer Agent：** 先创建并实现 Story 2.8，再继续 Story 7.6；
- **UX / Developer：** 新原型交互完成后，把实际行为回写 `EXPERIENCE.md`；
- **Story 7.7 开发者：** 只消费完成后的候选卡，不重新实现探索完成度判断。

### 成功标准

1. 无对话时用户能从四个入口开始；
2. Agent 每轮只推进一个缺失主干项，已填/已跳过项不反复追问；
3. 用户按需获取 2–4 个上下文相关回答思路，点击直接提交；
4. 用户能跳过，系统转下一项且不回头纠缠；
5. 7 项未完成时前后端均禁止整理，全部 `filled/skipped` 后明确收束并开放；
6. 右侧用户编辑线索不被 Agent 覆盖；
7. guidance、对话与线索刷新可恢复并保持租户隔离；
8. 真实浏览器完整走通该流程后，Story 7.6 才可进入 review。

### 时间与风险

- **预计影响：** 增加 1 个后端 Story，并使 7.6 延后到 2.8 完成后收尾；7.7 顺延；
- **主要风险：** LLM 结构化覆盖判断漂移、重复提问、跳过后的归纳过度；
- **控制：** 固定 7 字段枚举与状态机、后端硬门禁、结构化 schema 校验、单项推进测试、用户编辑优先、浏览器端到端验收。
