# Story 4.5: 分页阅读 + 段落批注 + 整体点评

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 读到生成正文的用户，
I want 分页阅读、对具体段落批注、对整章点评，
so that 我能像编辑一样精确地表达哪里要改。

## Acceptance Criteria

1. **分页阅读 + 翻页控件（FR19，UX-DR7）**：`reading` 态正文支持分页阅读，翻页控件「←/→」按边界 disabled（首页禁「上一页」、末页禁「下一页」，原型契约 EXPERIENCE.md:93），底部页码「NN / 总页数」（两位补零）。真实正文长度不定（4.4 冒烟 ~3500 字），**按段落数固定切页**（每页固定 N 段，`chapterGeneratedText` 拆段后分组，Jianghj 2026-08-05 决议）；只有 1 页时首末页边界同时命中（两个翻页键都 disabled）。

2. **翻页只移指针、不改数据 + 翻页清批注目标（原型契约）**：点「←/→」`chapterReaderPage ±1`，重渲染当前页正文；翻页**清当前批注目标**（`chapterAnnotationTarget=null`、`chapterAnnotationDraft=""`，EXPERIENCE.md:93「翻页清当前批注目标」），不清已保存批注列表、不清整体点评。**须重加 `[data-chapter-page]` 事件监听**——4.4 删除分页 UI 时一并删了该死监听（4.4 review Low patch，app.js `bindChapterCreationInteractions`），4.5 接入分页时重加。

3. **段落 `＋` 批注触发（FR19，原型 `paragraph-annotation-trigger`）**：每段悬浮显示 `＋` 按钮，点击进入批注模式——`chapterAnnotationTarget` 定位「该页该段」（`{page, paragraph}`），侧栏 textarea 的 label 切「批注第 N 段」、placeholder 切「写下对这一段的具体意见……」（原型 chapterContextMarkup app.js:3125-3127），保存后主动 `.focus()` 定位段落（UX-DR 焦点管理 EXPERIENCE.md:135）。**定稿后（`chapterFinalized`）不渲染 `＋` 触发器**（EXPERIENCE.md:94/112）。

4. **保存批注 → 进列表 + 可回定位（原型契约）**：批注 textarea 非空才可点「保存批注 →」（空则 disabled，app.js:3128），保存后批注 push 进本章批注列表（`chapterAnnotations` **内存数组，V1 不落库**，Jianghj 2026-08-05 决议——见 Dev Notes「批注/点评存储决策」），侧栏批注列表可悬浮展开（`chapter-annotation-summary` hover/focus-within，styles.css:2847）、点某条 `data-locate-annotation` 回定位到对应页/段（切 `chapterReaderPage` 到该段所在页 + `.focus()`，app.js:3380-3396）。已批注段落显示视觉标记（`has-annotation`，styles.css:3552）。

5. **整体点评（未选中段落时的默认态）**：未选中任何段落（`chapterAnnotationTarget=null`）时，textarea 为「对这一章的点评」整体点评，placeholder「例如：开头再快一点，强化收到来信时的不安感……」（原型 app.js:3125-3127），输入存 `chapterFeedback`（内存态）。批注模式与点评模式**共用同一 textarea**，靠 `isAnnotating = Boolean(chapterAnnotationTarget)` 切换 label/placeholder/绑定变量（app.js:3099/3109-3111）。

6. **批注 + 点评共同作为 4.6「改进本章」输入的开关（原型 `canImprove`）**：`canImprove = chapterFeedback.trim() || chapterAnnotations.length`（app.js:3112），「改进本章」按钮据此启用/禁用（无点评且无批注则 disabled），说明文案「段落批注和整体点评都会用于"改进本章"；"重新生成"会替换整章」（app.js:3128）。**本 story 只负责产出批注/点评并驱动 `canImprove` 开关 + 按钮禁用态**；「改进本章 →」/「重新生成」按钮点击后的真实流水线接入是 **Story 4.6 范围**——本 story 保留原型 900ms mock 修订逻辑不动（app.js:3397-3429），不接真实生成。
