# Story 1.4: 作品创建与列表持久化（空 / 失败状态）

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 登录用户，
I want 新建作品并看到真实持久化、按更新时间排序的作品列表，
so that 我能集中管理自己的多部小说。

## Acceptance Criteria

1. **Given** 我已登录且点「开始一本新小说」
   **When** 我走完两步弹窗——先选 `guided`（引导探索）/ `free`（自由探索），再填小说名（留空则「未命名小说」，原型 `app.js:1742-1746`）
   **Then** 系统创建归属当前 `user_id` 的 `project` 记录，`mode` 存所选模式（`guided`/`free`）、`phase` 初始为 `explore`，标题留空回落「未命名小说」
   **And** 与原型不同，新建**真实落库**，不再是仅跳转不持久化（原型 `app.js:1799` 仅 `location.hash` 跳转）

2. **Given** 我有 N 部作品
   **When** 我打开作品库（`#/projects`）
   **Then** 接口**仅返回属于我（当前 `user_id`）的作品**（NFR3 租户隔离），按 `updated_at` 倒序排列
   **And** header kicker 显示 `Library / NN novels`（数量补零两位，原型 `app.js:389`）

3. **Given** 我的账号一部作品都没有
   **When** 作品列表接口返回空数组
   **Then** 前端呈现 `empty` 空状态区块 `empty-library`（大标题「你的第一本小说，从这里开始。」+ 主按钮「开始一本新小说 →」，原型 `app.js:392`），kicker 显示 `00`
   **And** 后端**无需为空态做任何特殊分支**——空态是「真实空列表」的自然产物

4. **Given** 作品列表接口请求失败
   **When** 前端拿到错误
   **Then** 呈现 `error` 失败区块 `library-error`（标题「暂时无法读取你的作品。」+ 说明「连接恢复后可以重新加载，不会影响已经保存的内容。」+「重新加载」按钮，原型 `app.js:392`），点「重新加载」重新拉取
   **And** 后端故障出口统一走 error envelope `{code, message, detail}`（AR5），前端据此进入 error 态

### project 表字段决策表（消除 epics AC1 字面歧义，dev 照此建表）
epics AC1「字段含 id/title/mode/phase/attention/detail/updated，对齐原型 app.js」——原型这些是**列表展示数据**（`app.js:209-240` 硬编码数组）。多租户真实系统里须区分「真实状态」与「派生展示」：

| 原型字段 | V1 处置 | 说明 |
|---|---|---|
| `id` | ✅ 入库（UUID PK，继承 `UUIDPKMixin`） | 不可枚举，规避 IDOR |
| `title` | ✅ 入库（String 非空） | 留空回落「未命名小说」；1.5 可改名 |
| `mode` | ✅ 入库（String 枚举 `guided`/`free`） | **存英文枚举**，展示层转中文（原型 `app.js:369` 已有 `free?"自由探索":"引导探索"` 映射逻辑） |
| `phase` | ✅ 入库（String 枚举 `explore`/`chapter`/`archive`，默认 `explore`） | 新建初始 `explore`；1.6「继续创作」按 phase 路由，随创作推进更新。**存英文枚举**，展示转中文 |
| `updated` | ✅ **复用继承的 `updated_at`**（`TimestampMixin` 已带 `onupdate=func.now()`） | **勿建独立 `updated` 列**（wheel reinvention）；API 经 `UTCDateTime` 序列化为 `...Z`，前端格式化为「今天 16:40」 |
| `attention`/`detail`/`action` | ❎ **不建独立列**，phase 派生展示态 | 原型是硬编码 mock 串（"等待你"/"第 3 章草稿等待阅读"/"阅读草稿"）；真实值依赖后续 epic（探索/章节进度）。V1 由前端按 `phase` 渲染固定文案（`explore`→"继续设定"），后端只返回真实 `phase`。存冗余展示串必与真实进度不一致、且每次章节变动都要回写同步——过度设计 |

> **这是本 story 唯一的设计判断点**，已在文末「待澄清」列出请用户确认。若用户要求 `attention/detail` 必须落库，则改为可空 String 列，但仍不建 `updated` 独立列。

### 关键实现陷阱（务必规避）
- **陷阱①：新增模型必须在 `migrations/env.py` 登记 import。** `env.py:13` 现为 `from muse.models import account`。`Project` 放**新模块** `models/project.py`（非账户域，不塞进 account.py），故**必须补** `from muse.models import project`，否则 `autogenerate` 生成空迁移**却不报错**（1.1/1.2/1.3 三度预警）。同步在 `conftest.py:26` 附近补 import 供 `create_all` 建表。
- **陷阱②：`project` 是首张带 `user_id` 的业务表 → 租户守卫首次实装。** `repositories/base_repo.py` 至今是占位（1.3 明确「从 1.4 起才实装」）。**所有 project 查询/写入必须绑定 `user_id`**：列表 `where(user_id == current_user.id)`、创建写入 `user_id=current_user.id`。这是 NFR3 行级隔离的落地起点，1.5 改名/删除、后续所有业务表都将复用此守卫。
- **陷阱③：mode/phase 存英文枚举，不存中文展示串。** DB 存 `guided`/`free`、`explore`/`chapter`/`archive`；中文（"引导探索"/"章节创作"）是展示层的事。存中文会让枚举判断（1.6 按 phase 路由）脆弱且难维护。用 Pydantic `Literal` 在边界校验，DB 列用 `String`（与现有 models 风格一致，不引入 DB enum 类型）。
- **陷阱④：空态/失败态是前端契约，后端零特殊分支。** AC3 空态 = `GET /api/projects` 返回真实 `[]`（列表恰好为空的自然结果）；AC4 失败态 = 任何 5xx/网络故障，前端捕获后渲染 `library-error`。**后端不要写 `if empty` / `if error` 的特判**——空数组照常返回，故障照常抛 `ErrorEnvelope`/500 走全局 handler。原型 `?state=empty|error` 只是预览开关（`app.js:377-378`），非后端语义。
- **陷阱⑤：标题归一化在 service 层。** `title` 前端可留空提交，Pydantic 侧设 `str | None`；service `strip()` 后为空则回落 `"未命名小说"`（原型 `app.js:1745-1746` `value.trim() || "未命名小说"`）。勿在 schema 用 `min_length=1`（会 422 拒绝合法的留空提交）。

### 强制复用的基座 pattern（照抄，勿另起炉灶）
- **分层样板**：`routers/projects.py`（仅校验+分发）→ `services/project_service.py`（业务编排 + `commit`）→ `repositories/project_repo.py`（只 `flush`）→ `core/db.get_session`。**严格参照 `routers/auth.py:26-36` register 三段式**。
- **鉴权入口**：路由参数标注 `current_user: CurrentUser`（`core/deps.py:55`），自动完成 access token 校验 + 取 `User`；无/过期/非法 token 在依赖内 401（AC 未登录自动挡）。**这是 1.3 为 1.4 铺好的复用点，直接用，勿重造鉴权。**
- **SessionDep**：`SessionDep = Annotated[AsyncSession, Depends(get_session)]`（`routers/auth.py:23` 已有此别名可参照；`core/deps.py:24` 亦导出 `SessionDep`）。
- **schema 边界（AR4）**：新 schema 继承 `schemas/base.py:CamelModel`（L29-34）。DB `updated_at` → API `updatedAt` 自动 camel；前端提交 camelCase 自动映射 snake。**禁止两端手写不一致字段名。**
- **时间序列化（AR5）**：`ProjectResponse.updated_at` 标注 `schemas/base.py:UTCDateTime`（L25），输出带 `Z` 后缀 ISO 8601。
- **错误 envelope（AR5）**：如需业务错误抛 `core/errors.py:ErrorEnvelope`；全局 handler 已注册，无需自行 try/except 兜底 500。
- **事务边界**：repo `flush`、service `commit`（照 `auth_service.register` L97-118 的样板：写入后 `await session.commit()`）。
