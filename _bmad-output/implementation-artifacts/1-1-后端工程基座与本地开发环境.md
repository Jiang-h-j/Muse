# Story 1.1: 后端工程基座与本地开发环境

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Muse 后端开发者，
I want 一套可运行的 FastAPI 分层骨架、迁移框架与本地依赖环境，
so that 后续所有账户/作品/创作能力都能在统一、可迁移、多租户就绪的地基上开发。

## Acceptance Criteria

**AC1 — 本地依赖环境起得来（AR10/AR21）**
- **Given** 一台装好 uv、Docker 的开发机
- **When** 按 README 执行初始化（`uv sync` 安装依赖）并 `docker-compose up -d`
- **Then** 本地起得来 PostgreSQL（启用 pgvector 扩展）+ Redis 两个容器
- **And** 应用启动后 `GET /health` 返回 200，且响应体能证明已连通 DB（如执行 `SELECT 1` 成功）

**AC2 — 分层架构与独立域就位（AR2）**
- **Given** 已初始化的后端仓库
- **When** 查看目录结构
- **Then** 存在 `routers`/`services`/`repositories`/`models`/`schemas` 分层与 `orchestration`/`providers`/`rag`/`tasks`/`core` 独立域
- **And** `routers` 仅做入参校验 + 分发，业务不写在 router 内（本 story 以 `health` router 作为该约定的示范样板）

**AC3 — 大小写边界转换收敛在 schema 层（AR4）**
- **Given** 分层骨架已就位
- **When** 定义任一 Pydantic response schema 并通过接口返回
- **Then** DB 层字段为 snake_case、API 边界自动转 camelCase（`alias_generator=to_camel, populate_by_name=True`），转换只收敛在 schema 层
- **And** `GET /health` 的响应体即用一个带下划线字段的内部模型（如 `db_connected`）验证边界产出 camelCase（`dbConnected`）

**AC4 — 统一 error envelope 与 ISO 8601 UTC（AR5）**
- **Given** 分层骨架已就位
- **When** 任一接口报错（含全局异常、HTTP 异常、请求校验错误）
- **Then** 返回统一 error envelope `{code, message, detail}`
- **And** 所有时间字段为 ISO 8601 UTC 字符串（形如 `2026-07-23T08:00:00Z`）
- **And** 提供一个临时可触发错误的探针端点（如 `GET /health/error-probe`，仅本 story 用于验证 envelope，后续可删）

**AC5 — Alembic async 迁移框架可空跑（AR7）**
- **Given** Alembic 已按 async 模板初始化（`alembic init -t async`）并改用项目实际的 async driver 与 settings
- **When** 执行 `alembic upgrade head`（此时尚无业务表）
- **Then** 迁移链可空跑通过（无业务表也不报错）
- **And** `alembic revision --autogenerate` 能基于项目 `Base.metadata` 正常生成迁移文件（此时应生成"空 diff"迁移，证明 autogenerate 已正确挂到 metadata target）

**AC6 — 原型静态可访问 + 预留 Vite 入口（AR1，铁律：不破坏原型契约）**
- **Given** 已有前端原型 `prototype/app/{index.html, app.js, styles.css}`
- **When** 用任意静态服务器（如 `python -m http.server`）以 `prototype/app` 为根访问
- **Then** 原型页面照常渲染、形态不变，`prototype/app` 三件套一字节不改
- **And** README 记录未来 Vite 渐进增强的接入姿势（以 `prototype/app` 为 root、复用现有 `index.html`、极简 `vite.config.js`），**本 story 不执行任何会生成/覆盖原型文件的命令**（严禁 `npm create vite`）

### 关键实现陷阱（务必规避）
- **陷阱①：Alembic async 模板默认 driver 是 asyncpg，但本项目定的是 psycopg3。** `alembic init -t async` 生成的 `env.py` / 依赖假设常指向 `asyncpg`；architecture.md:120/133 明确用 `psycopg[binary]`（psycopg3）。**必须**把 DSN 统一为 `postgresql+psycopg://user:pass@host/db`，并确保 `env.py` 用同一 async DSN。不要额外装 asyncpg。
- **陷阱②：pgvector 扩展不会自动存在。** 用 `pgvector/pgvector:pg16` 镜像（预装扩展二进制），并在 initdb 脚本里 `CREATE EXTENSION IF NOT EXISTS vector;`。普通 `postgres:16` 镜像没有该扩展会导致后续 Epic 5 建 embedding 表失败——本 story 就把扩展装好。
- **陷阱③：base.py 不要提前加 user_id/project_id。** 架构 L394 描述 base 为「带 id/user_id/project_id 的 Base mixin」，但那是终态愿景；此刻 user/project 表尚不存在，加了就是无 FK 约束的裸列或悬空 FK。本 story 只放 `id` + 时间戳，租户列由 1.2（user）/1.4（project）建表时各自定义并补 FK。
- **陷阱④：不得跑 `npm create vite`。** 原型入口是传统 `<script src="./app.js">`（见 prototype/app/index.html:18），vite vanilla 模板入口是 `type=module src=/main.js` 且会生成同名 index.html/style.css 覆盖原型。**违反「原型=唯一契约事实基准」铁律。** Vite 仅在 README 记录预留姿势。

### 强制遵循的架构约定（AR 对应）
- **AR4 大小写边界**：DB/ORM/repository 全 snake_case；API 出入参 camelCase；转换点**唯一**落在 Pydantic schema 的 `alias_generator=to_camel, populate_by_name=True`。禁止在两端手写不一致字段名。（architecture.md:285-289）
- **AR5 error envelope**：统一 `{code, message, detail}`，HTTP 状态码语义化；时间一律 ISO 8601 UTC 字符串。（architecture.md:330-332）
- **AR2 分层边界**：`routers` 仅校验+分发，不得直查 model；`services` 不得绕过 `repositories`。本 story 的 health 端点即按此走 router→service。（architecture.md:441-442）
- **租户守卫（本 story 仅铺垫）**：所有业务查询后续须经 repository 且带 `user_id`+`project_id`。本 story 无业务表，只把 `repositories/` 目录与 `base_repo` 占位建好，守卫逻辑 1.2 起实现。（architecture.md:349-350, 357）
- **Provider 唯一入口（本 story 仅建目录）**：后续 LLM/embedding 调用只经 `providers/`。本 story 不实现。（architecture.md:340-343）

### 技术栈与版本（architecture.md 已联网核实，2026-07）
- Python 3.12+ / FastAPI（`fastapi[standard]`，含 uvicorn/CLI）；依赖管理 uv。

- 说明：`openai`/`python-jose`/`passlib` 本 story 只作为依赖装上（为 1.2/1.3/Epic 2 铺底），**不写调用逻辑**。

### Debug Log References

实现中遇到并解决的关键问题：
1. **PyPI 直连极慢卡死 uv sync**：直连 pypi.org 下行 ~46KB/s，79 个包卡 20+ 分钟无进展。改用清华镜像（~4.8MB/s）后 15.7s 装完。已把镜像持久化到 `pyproject.toml` 的 `[[tool.uv.index]]`（default=true）。
2. **Docker 桌面版被公司禁用**：改用机器上已装的 Colima（`colima start` 拉起 docker daemon），现有 `docker`/`docker compose` 命令零改动直接可用。
3. **alembic 报 `No module named 'greenlet'`**：SQLAlchemy async 在 alembic 的 `run_sync` 同步上下文里需要 greenlet，Python 3.13 未自动装。`uv add greenlet` 补上后 `upgrade head` 空跑通过。
4. **ruff 拦 alembic 生成的迁移文件**（`op`/`sa` 未用、`Union` 老式导入等 7 处）：迁移文件是生成物，加 `extend-exclude = ["migrations/versions"]` 排除。
