# Story 2.4: 引导探索——翻页与答案真实持久化

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 引导探索中的用户，
I want 前后翻看并修改已答题、且我的答案不会丢，
so that 我能反复斟酌、不怕刷新或中断丢失进度。

## Acceptance Criteria

> **净新增能力只有 AC5-后端。** AC1/AC2/AC3/AC4 是**原型已实现的问卷式翻页交互契约**（FR7、UX-DR4，页面即契约），
> 事实源是 `prototype/app/app.js`，本 story **不改 `app.js`、不回归这些契约**——它们由原型保持。本 story 只交付
> AC5 缺失的「引导答案真实持久化」后端能力：`exploration_message` 表 + 存/取 API + 测试（补原型「内存态、
> 刷新即丢」的落差）。**AC5 的「刷新/断线后恢复」中『前端进探索页 GET 回填 `explorationHistory`』这一步是纯前端行为**，
> 与首个 fetch/token/401 横切基座一并 **defer 至「引导探索前端集成切片」**（见 Dev Notes「受控决策 A」，
> 合并 2.3 already-deferred 的 interpret 接线）。故本 story 对 AC5 的验证边界 = **存取 API 契约 + 真实落库 + 恢复查询返回已答**，
> 浏览器端到端回填由前端集成切片兑现。

1. **Given** 我在引导探索翻页（FR7，UX-DR4）
   **When** 底部导航渲染
   **Then** 「← 上一题」「下一题 →」按可用性显示（`canPrev = explorationView > 0` app.js:816、`canNext = explorationView < answeredCount` app.js:817，`answeredCount = explorationHistory.length` app.js:795）；不可用一侧以 `guided-nav-placeholder` spacer 留空占位保持两端对齐（app.js:809,820）；整理中过渡态不出常规翻页栏（app.js:810-814）。**本 story 后端 only，此契约由原型保持、不回归。**

2. **Given** 我翻到别的题
   **When** 前翻或后翻
   **Then** 不清除任何已答答案——翻页只移动指针 `explorationView`（`data-guided-back` app.js:993-996 `explorationView -= 1`、`data-guided-next` app.js:1000-1003 `explorationView += 1`），`explorationHistory` 数组不变（指针/进度解耦，app.js:108-110、EXPERIENCE.md:118）。**本 story 后端 only，此契约由原型保持、不回归。**

3. **Given** 我翻回一道已答题
   **When** 页面渲染该题
   **Then** 高亮我上次所选项（按已存 `answer` 的 value 匹配当前题选项：`isChosen = savedAnswer && option.value === savedAnswer` → `is-chosen` + `✓` + `aria-pressed`，app.js:848-857）；若上次是自述作答（答案不匹配任何选项，`savedIsCustom` app.js:862-863）则回填自述文本到输入框（`customValue` app.js:864,870,878）。**本 story 后端 only，此契约由原型保持、不回归。**

4. **Given** 我在已答题重选答案
   **When** 提交
   **Then** 只更新该题答案——按当前翻页位置定点写 `explorationHistory[explorationView] = {question, answer}`（app.js:458-461），不影响其后任何题；重选后前进回到「已答进度」的下一题（`wasAnswered ? explorationView + 1 : explorationHistory.length`，app.js:457,476）。**本 story 后端 only，此契约由原型保持、不回归。**

5. **Given** FR11 要求探索答案真实持久化（补原型「内存态、刷新即丢」落差——原型 `explorationHistory` 是 JS 变量 app.js:102，`sessionStorage` 仅存模式/待确认设定、**不存引导答案** EXPERIENCE.md:24,31）
   **When** 我作答或修改后刷新/断线重连
   **Then** 答案已落库 `exploration_message`（带 `user_id` + `project_id` + `session_id`，行级租户隔离 NFR3）、可恢复、不丢失进度。**本 story 交付此能力的后端**：① 保存单题答案的写端点（每次作答/改答 upsert 一条，重选定点覆盖同题位）；② 取回本会话全部已答的读端点（供前端进探索页回填 `explorationHistory`）；③ `exploration_message` 表（Epic 2 按需建表 epics.md:455）。**前端 GET 回填 + POST 落库接线 defer 至前端集成切片**（受控决策 A）。

  - [x] `async def upsert_guided_answer(session, *, user_id, project_id, session_id, question_index, question, answer, answer_type) -> ExplorationMessage`：定点写该题位答案，已存在（撞 `(session_id, question_index)` 唯一约束）则覆盖。**推荐 PG 原生 upsert**（`from sqlalchemy.dialects.postgresql import insert`；`insert(ExplorationMessage).values(...).on_conflict_do_update(constraint="uq_exploration_message_session_id_question_index", set_={...})`）——一次往返、并发安全（仿 2.2 用唯一约束兜底并发 TOCTOU 的精神，且比「先查后写」少一次往返）。

    - repo 只 flush（`await session.flush()` 拿 id），事务边界（commit）归 service（延续 base_repo 约定）。
    - **若 dev 判断 ORM「先查后写」更可控**（get_by_session_and_index → 有则改字段属性触发 onupdate / 无则 add）亦可，但需自己处理并发 TOCTOU（唯一约束 IntegrityError → rollback → 重查改，仿 exploration_service:52-66）——PG upsert 更省，记 Completion Notes 说明选型。

### 🔑 受控决策 B（Jianghj 2026-07-28 授权「一样看你的想法」）：`exploration_message` 最小结构 + `(session_id, question_index)` 唯一约束

- **表名遵循架构**：architecture.md:236,293 既定 `exploration_message`（「对话与线索持久化」的统称容器），**不自造 `exploration_answer`**。引导答案是其 V1 落地形态；表名「message」与引导「问答对」有轻微语义张力，但遵循架构既定命名优先。

### 关键实现陷阱（务必规避）

- **陷阱①：租户守卫二义合一 404（承 2.2 陷阱①）。** 存/取答案先 `get_owned_project(session, project_id, user_id)`——None 即 404 `project_not_found`，**不写 403、不区分「不属于我」与「不存在」**（IDOR 侦察面 NFR3）。复用 `_exploration_not_found()`，勿新造 code。
- **陷阱②：PG upsert 的 `onupdate` 不触发——`set_` 必须显式 `updated_at=func.now()`。** SQLAlchemy 列级 `onupdate=func.now()`（base.py:26）只在 ORM unit-of-work / core `update()` 触发；`on_conflict_do_update` 走 core insert 路径**不触发**。漏写则重选覆盖后 `updated_at` 停在首答时间，违反 [[project_muse_updated_at_semantics]]（改答即刷新）。测试须断言改答后时间戳刷新。
- **陷阱③：DO UPDATE 不覆盖 `created_at`。** `set_` 只更 `answer`/`answer_type`/`question`/`updated_at`，保留首答 `created_at`。`values(...)` 给插入分支全列，`set_` 只给更新分支要改的列。
- **陷阱④：get-or-create session 复用 `enter_exploration`，别自造。** 作答隐含探索已开始——`save_guided_answer` 内调 `enter_exploration`（幂等 get-or-create，含并发兜底 + mode 单一事实源 exploration_service.py:35-66）拿 `session_id`；自己写「get 判空 build」会漏并发防线。
- **陷阱⑤：唯一约束是 `(session_id, question_index)` 不是 `(project_id, question_index)`。** 答案挂会话根；虽 V1 一 project 一 session，用 session_id 更贴领域、与 2.6 扩展一致。
- **陷阱⑥：GET 空态返 `[]` 不是 404（陷阱⑨同）。** session 不存在（没进探索）或没答过 → 空列表（自然空态，200）。只有 project 越权/不存在才 404。
- **陷阱⑦：POST 幂等返 200 不是 201（承 2.2 陷阱⑦）。** upsert 语义——重复保存/改答返同题位最新态，非恒新建。
- **陷阱⑧：入参校验齐全（422）。** `answer_type` 用 `Literal["option","custom"]`（非法值 422）；`question_index` `ge=0`；`question`/`answer` 复用 `_NonBlankText`（空/纯空白/超长 2000 → 422）。
- **陷阱⑨：本 story 不调 LLM、不涉护栏、不涉流式。** 存/取答案是纯 CRUD——选项 value 与自述凝练结果都在**别处产出后**才 POST 落库。别引入 provider / check_quota / EventSourceResponse / ARQ / Redis（这些是 2.3 interpret / 2.5 整理任务的事）。测试不需 `@requires_redis`/`@requires_deepseek`。
- **陷阱⑩：`answer_type` 是引导作答路径的领域事实，非为 2.6 预留。** 本表 V1 只服务引导；自由对话（2.6 追加式流）形态不同，届时再定表扩展。别现在就往表里塞 role/content/sequence 等自由对话列（YAGNI，受控决策 B）。
- **陷阱⑪：`app.js` 一字节不改（受控决策 A）。** 引导页接线 + token/fetch 基座 defer 至前端集成切片。`git status prototype/` 须为空、`fetch(` 计数保持 0。
- **陷阱⑫：时间戳测试勿用 `time.sleep`（[[feedback_timely_commit]] 关联、test_projects.py 已清此反模式）。** 验 `updated_at` 刷新用确定性手段（断言 ≥ created_at 且内容已覆盖，或比较两次响应时间戳），别 sleep 制造时间差。
