# Story 1.8: 托管免费额度护栏与用量展示

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 走托管默认路径的用户，
I want 看到自己的用量与剩余免费额度、并在触顶时得到明确提示，
so that 我清楚免费边界、不会莫名被拒。

## Acceptance Criteria

1. **Given** 需要按账户累计用量（建 `usage_ledger` 表，AR9/AR14）
   **When** 本 story 建立表结构 + `usage_repo` DAO + `usage_service` 护栏校验框架
   **Then** 表可记录每账户的 tokens 与成本累计（至少：`user_id` 租户列、`project_id`（可空，账户级聚合优先）、`prompt_tokens`/`completion_tokens`/`total_tokens`、`cost`（成本，Decimal）、`billing_path`（`hosted`/`byok` 区分归账面）、时间戳）；**本 story 只建表 + 校验框架 + 展示，实际用量写入的埋点由 Epic 2 Provider 层填**（AR14 跨 epic 依赖，见 Dev Notes「跨 Epic 边界」）——本 story 交付「供 Provider 层调用的记账写入接口」但**不自行触发 LLM 调用、不埋点到任何生成链路**

2. **Given** 我走托管路径发起生成（未绑定 BYOK）
   **When** `usage_service` 校验免费额度（护栏在「发起生成前」被调用，供 Epic 2 生成链路消费）
   **Then** 未触顶 → 正常放行（返回剩余额度信息，不抛错）；触顶 → 抛 `ErrorEnvelope`（沿用登录限流的 **`429` 先例**，`code="quota_exceeded"`，`detail` 附前端可读位如 `{quotaExceeded: true, used, quota}`），**不静默失败**（AR6「触顶返回明确提示」）
   **And** 免费额度具体阈值**可配置**（`core/settings.py` 新增字段，如 `free_quota_chapters`/`free_quota_tokens`），默认值待 Epic 4 盲测出单章真实成本后再定——**本 story 用可配置占位阈值**（占位默认值对齐原型 `quotaChapters = 5`，app.js:2081）

3. **Given** 我进入设置页/用量入口（原型 `renderByok()` 的 `hosted` tab，`app.js:2096-2100`，路由 `#/settings/model-access`；UX-DR2）
   **When** 页面加载（后端提供 `GET /api/usage` 查询接口）
   **Then** 返回我的托管用量与剩余免费额度（`used`/`quota`/`remaining`/`resetAt` 等，camelCase 边界）；**BYOK 用户**返回「走自有 Key、不占免费额度」的语义态（如 `{billingPath: "byok", quotaApplies: false}`），与原型 `byok` tab 文案「Muse 不再计免费额度」（app.js:2104）一致

4. **Given** 我已绑定 BYOK（Story 1.7）
   **When** 我发起生成 / 查询用量
   **Then** 用量记我自己账（`billing_path="byok"`，**不计入托管免费额度**，NFR5），额度护栏**不拦截**（`usage_service` 校验时先判 BYOK：已绑定即直接放行，判据用 `byok_service.get_decrypted_key_for_user(...) is not None` 或 `get_binding_status(...)`，见 Dev Notes）

    - **Task 7 测试须防固化错口径**：若最终用 A，测试按「插到 tokens 阈值 →429」而非「插 5 行 →429」；若用 B，按 DISTINCT 章数触顶。**别写「插满 5 条流水 →429」这种会掩盖 COUNT(*)≠章数 的用例**

### 关键实现陷阱（务必规避）
- **陷阱①：`usage_ledger.user_id` 不是 unique —— 与 1.7 ByokKey 相反。** BYOK 是账户级单例（`user_id` unique，每账户至多一条）；用量是**一对多流水**（每次 LLM 调用一行，同账户 N 行）。**别照抄 ByokKey 的 `unique=True`**——`user_id` 只加 `index=True`（加速聚合查询），无唯一约束。
- **陷阱②：`cost` 用 `Numeric`/`Decimal`，绝不用 `Float`。** 成本是钱，浮点累加会漂移（0.1+0.2≠0.3）。ORM 用 `Mapped[Decimal]` + `mapped_column(Numeric(12,6))`，Python 侧全程 `from decimal import Decimal`，**别在任何环节转 float**（包括聚合、schema 序列化）。schema 里 cost 若要返回，用 `Decimal` 或转字符串，勿转 float。V1 展示以「章」为主，cost 主要供成本审计与 Epic 4 盲测定档，展示层可暂不返 cost。
- **陷阱③：护栏 `check_quota` 必须「BYOK 优先短路」。** 校验顺序**先判 BYOK 再判额度**：已绑定 BYOK → 立即放行（`quotaApplies=false`），**根本不查 usage 累计、不比阈值**（AC4「额度护栏不拦截」）。若顺序反了（先查额度再判 BYOK），BYOK 重度用户会被托管额度误拦。判据用 `byok_service.get_decrypted_key_for_user(session, user_id) is not None` 或 `get_binding_status(...)`（byok_service.py:119/137）。
- **陷阱④：触顶返 `429` 而非 500/静默，`detail` 带前端可读位。** AR6「触顶返回明确提示」、AC2「不静默失败」。用 `ErrorEnvelope("quota_exceeded", "…", detail={"quotaExceeded": True, ...}, http_status=429)`——**429 沿用登录限流 `too_many_attempts` 先例**（auth_service 的登录失败超阈值返 429 + `detail:{locked:True}`），与全项目「detail 附前端可读布尔位对接原型态」约定一致（原型有 expired/invalid/locked 等状态位，architecture.md:175）。**别用 402 Payment Required**（原型文案明说「写作过程中不会弹付费墙」app.js:2099，触顶是「今日额度用完」非「要付费」，语义是限流不是收费）。
- **陷阱⑤：展示 `get_usage_view` 只读、不抛额度错误。** 查看用量的接口**不该因触顶而失败**——用户额度用完了更需要看到「5/5 已用完」的展示。`get_usage_view` 与 `check_quota` **分离**：前者永远 200 返回当前状态（含 used==quota 的满格态），后者才在生成前校验并可能抛 429。别把护栏校验塞进展示查询。
- **陷阱⑥：`SUM` 空结果返 0 不返 None。** 新用户无任何 usage_ledger 行时 `SUM(total_tokens)` 聚合，PG 的 `SUM` 空集返 NULL（`COUNT` 返 0）。用 `func.coalesce(func.sum(...), 0)` 或 Python 侧 `result or 0` 兜底，**别让 None 流到 `remaining = quota - used` 里**（None 参与算术 → TypeError → 500）。
- **陷阱⑦：租户守卫贯穿所有 usage 查询（NFR3）。** `record_usage`/`sum_hosted_usage`/`get_usage_view` 全部 `where(UsageLedger.user_id == current)`。查他人用量一律等同「自己 0 用量」，**不泄露他人用量**（参照 `account_repo.get_byok_by_user` account_repo.py:64 的租户过滤，及 `project_repo` IDOR 消除范式）。router 用 `CurrentUser.id`，路径**不带** user_id。
- **陷阱⑧：`billing_path` 记账口径 = 记账那刻的绑定态，护栏用 hosted 累计。** `record_usage` 的 `billing_path` 由调用方（Epic 2 Provider）按「本次调用是否走 BYOK」传入——**这是 Epic 2 的职责，本 story 只存该列**。护栏 `sum_hosted_usage` 只累计 `billing_path="hosted"` 的行（BYOK 行不占额度，NFR5/AC4）。别把 byok 行算进托管额度累计。
