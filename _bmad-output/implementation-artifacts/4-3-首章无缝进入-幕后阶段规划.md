# Story 4.3: 首章无缝进入 + 幕后阶段规划

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 刚确认设定的用户，
I want 直接进入第一章创作，不被阶段规划的过程打扰，
so that 我的注意力始终在「写我的故事」而非管理流程。

## Acceptance Criteria

> 来源：epics.md:917-939（Story 4.3）+ FR17（epics.md:66）+ NFR4 长程一致性（epics.md:50、architecture.md:50）+ Epic 4 关键边界④（epics.md:859）+ 原型 app.js 锚点（568/1120-1129/575，实际现行行号见 Dev Notes）+ 3.5 confirm 衔接（story_settle_agent.py:599-631）+ 4.2 流水线/异步范式（pipeline.py、worker.py:118-217）。

**AC1 · 确认设定后阶段规划全程幕后、用户体感直接进第一章（FR17）**
Given 我确认了故事设定（接 Epic 3 Story 3.5——`confirm_profile_card` 同事务翻 confirmed + phase explore→chapter，story_settle_agent.py:599-631；前端 `confirmStoryProfileAndEnterChapter` 已接真实 `confirmProfile` 并跳 `chapters/1`，app.js:1963-2013）
When 我进入创作
Then 首个阶段规划（**阶段目标 + 章节骨架**）**全程幕后完成、不展示、无确认弹窗**（FR17）；confirm 请求**不被阶段规划的 LLM 调用阻塞**——confirm 立即返回、phase 已进 chapter，阶段规划在后台异步生成（触发/同步模型见 Dev Notes「幕后触发决策」）；我体感**直接进第一章**（`#/projects/{id}/chapters/1`）。**绝不新增阶段规划问答页 / 确认按钮**（原型 `explorationMode==="stage"` 已归位 profile，app.js:2242-2245，V1 不得复活）。

**AC2 · 阶段规划基于真实故事设定生成、替代前端 mock（替 `buildCurrentStagePlan`）**
Given 原型阶段计划是纯前端 mock——章数写死（`Math.min(7, Math.max(3, …||5))`，恒缺省 5）、模板化标题/文案、`stagePlanningDraft` 恒空（app.js:2191-2237）
When V1 实现
Then 阶段规划**基于 confirmed story_bible（12 字段 + style_profile）真实生成**（LLM 产出阶段目标 + 章节骨架列表：每章 `title` + `brief`）替代 mock；**章节数按剧情需要、不写死**（不再 clamp 到 3-7）；NFR4 一致性按「几百章」设计、**不设人为章数上限**（epics.md:935、architecture.md:50/241）。阶段规划**落库持久化**（重进不重生成、断线可恢复——最小存储方案见 Dev Notes）。

**AC3 · 阶段计划仅作第一章右侧 `chapter-context` 侧栏参考展示（无确认按钮）**
Given 阶段计划幕后生成
When 章节页渲染（`chapterCreationState !== "reading"` 的输入/生成态侧栏）
Then 阶段计划**仅作右侧 `chapter-context` 侧栏参考展示、无确认按钮**（原型 `chapterContextMarkup` 非 reading 分支，app.js:2767-2776）；固定文案「**阶段计划提供每章的方向；详细章节计划只在准备创作当前章时生成。**」（app.js:2769 逐字保留）；侧栏渲染**真实阶段计划数据**（替代 `chapterStagePlan()→buildCurrentStagePlan()` mock，app.js:2727-2728），列出各章 `title`/`brief`，`is-current` 高亮当前章（`chapterCreationIndex`）。

**AC4 · 进入第一章为输入态（等待本章想法或直接生成）**
Given 我进入第一章
When 页面初始
Then 章节创作状态为**输入态**（`chapterCreationState="input"`，原型 app.js:186/2009/2850-2860）；渲染「本章想法」可选输入框 + 生成按钮（原型输入态 markup，app.js:2851-2860）——**本 story 到此为止（渲染输入态 UI）**；**点击生成→真实调用 4.2 流水线生成正文、本章想法入参、生成过渡/阅读态全归 Story 4.4**（边界见 Dev Notes「与 4.4 的边界」）。第一章的章标题/brief 取自 AC2 阶段规划的第 1 章骨架。

**AC5 · 章节页消费路由真实 projectId（还前端接线债）**
Given 原型章节页硬编码 `demo`（返回链接 `#/projects/demo/explore`、归档跳 `#/projects/demo/archive`、下一章 `#/projects/demo/chapters/N`，app.js:2876/3022/3301），且 `render()` 的 `chapterMatch` 已解析真实 `projectId`+章号却未被 `renderChapterCreation` 消费（app.js:4324-4326、render chapter 分支只调 `renderChapterCreation()` 不传 id）
When 本 story 接线第一章
Then 章节页**消费路由真实 projectId**（`chapterMatch[1]`）拉取该作品的真实阶段规划并渲染；章节页内部路由锚点（返回探索/侧栏/章号）用真实 projectId 替换 `demo` 硬编码。**范围克制**：只打通「第一章输入态 + 侧栏阶段计划」所需的接线；归档跳转/下一章循环/阶段交界等属 4.5-4.7，本 story 不接（仅把硬编码 `demo` 收敛到不阻塞第一章渲染，其余页锚点保留占位或延后，dev 判断最小改动面）。

**AC6 · 异步任务模型 + SSE（复用 4.2/2.1 底座，NFR2 不阻塞不轮询）**
Given 阶段规划是 LLM 调用、confirm 不应同步阻塞（AC1）
When 触发幕后生成
Then 走异步任务模型：**新增 ARQ 任务生成阶段规划**（承 `settle_exploration` 范式，worker.py:118-184），confirm 成功后触发（触发点见 Dev Notes「幕后触发决策」——由 confirm 服务或前端 confirm 成功回调发起，`register_task_owner` 必先于 `enqueue_job`，exploration_service.py:298-307）；前端**经 SSE 消费**（`taskEvents` 范式，app.js:1485-1505 / api.js:361-472）progress/result/error、**不轮询**；第一章侧栏在阶段规划就绪前显示**加载/占位态**、就绪后渲染真实数据（无终态兜底防永久 spinner，仿 app.js:1509-1514）。

**AC7 · 记账正确性 + 租户守卫（每次 LLM 走 MeteredProvider，AR14/NFR5）**
Given 阶段规划各 LLM 调用成本须按 project 累计（NFR5）、记账埋点在 Provider 层（AR14）

**AC8 · 范围边界——阶段规划幕后生成 + 第一章输入态接线，不做正文生成/循环/交界（受控决策，创始人 2026-08-04 授权自主定夺）**
Given epics 线性依赖 4.3→4.4→…→4.7；4.4 做正文生成、4.5 阅读批注、4.6 改进重生、4.7 定稿循环+阶段交界

Then 本 story **只交付**：阶段规划 LLM 生成 service + 最小存储 + ARQ 任务 + confirm 幕后触发 + 第一章「输入态 + 真实阶段计划侧栏」前端接线 + 章节页真实 projectId + 单测/装置验证。**不交付**：正文生成流水线接入（4.2 已备底座、4.4 接入）、本章想法真实入参生成、生成过渡/阅读态、段落批注/点评（4.5）、改进/重生（4.6）、定稿/阶段循环/阶段交界方向输入（4.7）、data-agent/章节卡片（Epic 5）。**阶段循环幕后推进（FR22）本 story 不做**——仅首个阶段规划。

## Dev Notes

### 本 story 的性质：阶段规划幕后生成 + 第一章输入态接线（端到端，AC8 范围边界）

这是 Epic 4「无缝创作闭环」的**入口体验**——用户确认设定后**体感直接进第一章**、注意力不被流程管理打断（FR17）。本 story 端到端打通「确认设定 → 幕后异步生成首个阶段规划（阶段目标 + 章节骨架）→ 落库 → 第一章右侧侧栏读真实阶段计划 → 输入态等待创作」。**与 4.2 的关系**：4.2 是**章节正文**四段流水线底座（context→drafter→reviewer→polisher，产出整章正文）；本 story 生成的是**更高层的阶段规划**（阶段目标 + 各章 title/brief 骨架，一次较轻的 LLM 调用），是 4.4 正文生成的**上游纲领**。二者是不同产物、不同粒度，本 story 不复用四段流水线（那是写整章正文）、只借其 service/异步/记账范式。

### 交付边界=端到端（创始人 2026-08-04 授权自主定夺，依据 [[feedback_design_decision_delegation]]）

**决策**：本 story 做**端到端**（后端生成+存储+触发 + 前端接线），不止于纯后端底座。理由：
- 4.3 的 AC（epics.md:917-939）**几乎全是前端体验描述**（无缝进入、侧栏真实阶段计划展示、输入态）——纯后端交付无法验证 AC1/AC3/AC4，与 story 本意（「用户体感」）背离。
- Epic 4 边界「4.4 才前端接线」（epics.md:859）**是针对正文生成**（4.4 AC 明写「替换原型 1200ms mock + 硬编码 3 页」正文 mock）。4.3 替换的是**另一个 mock**（`buildCurrentStagePlan` 阶段计划 mock），两个 mock 边界不冲突。4.3 做阶段计划前端、4.4 做正文前端，各司其职。
- **严守下游边界**：本 story 前端**只到输入态渲染**（AC4）——点击生成→正文流水线、生成过渡、阅读态、批注全归 4.4-4.5。不越界做正文。

### 幕后触发决策（AC1/AC6——confirm 不被 LLM 阻塞）

**决策：confirm 立即返回、阶段规划异步幕后生成（ARQ + SSE）**，confirm 端点/事务不动（保 3.5 原子性）。理由：
- FR17「用户体感直接进第一章」——若 confirm 同步等 LLM（数秒），用户会卡在确认按钮上转圈，违背「无缝/不打扰」本意。
- 3.5 confirm 是**纯状态流转无 LLM**（story_settle_agent.py:607「无 LLM、无护栏」）、同事务翻 confirmed+phase。若在其中同步塞 LLM 调用，会破坏该原子事务的纯粹性、且 LLM 失败会牵连 confirm（用户设定没确认成）。
- 契合项目既有异步范式（探索 settle、4.2 generate_chapter 都是 POST→taskId→SSE）。
- **触发点二选一（Task 3，dev 定）**：① 前端 confirm 成功回调发起阶段规划 POST（推荐——confirm 端点职责单一、与 settle 触发范式一致、前端已有 SSE 地基）；② confirm 服务内事务提交后 enqueue。推荐①，边界最干净。

### 阶段规划存储决策（AC2——落库持久化）

**决策倾向：新建独立最小表**（Task 2 方案①），照 4.2 `chapter_generation_run` 先例（基础设施/运行时状态表，不属 Epic 4「按需建表：无」的业务表约束——同 4.2 断点续跑表的论证，epics.md:858 指业务表）。字段最小：user_id+project_id（索引+FK）、阶段目标 Text、章节骨架 JSONB `[{title,brief}]`、幂等键 `(user_id, project_id)`（首阶段一行；留 `stage_number` 扩展位供 4.7 循环，但本 story 只写首阶段）。**不选** story_state（Epic 5 归档五表，V1 未建，引入即越界预支 Epic 5）。dev 若有更优最小方案（如复用 chapter_generation_run 的 steps JSONB 存阶段规划）可自主定，但须保证「重进不重生成、断线可恢复」。

### model 档决策（阶段规划用思考档 pro，参 4.2）

4.2 已定 drafter/reviewer/polisher 全用思考档 `deepseek-v4-pro`（写长正文/审查重、快档会把内容放进 reasoning_content 致空产，见 4.2 Debug Log）。阶段规划是**结构化纲领生成**（阶段目标 + N 章骨架），比整章正文轻、比 12 字段凝练略重。**建议思考档 pro**（保证规划质量、避免快档空产陷阱，story_settle_agent.py:55-58）；`max_tokens` 留足 reasoning 预算（骨架体量不大，2000-3000 应足，dev 据装置产样调）。dev 可据成本/质量实测调档并在 Completion Notes 记明。

### 与 4.4 的边界（防范围蔓延）

- **正文生成接入**（真实调 4.2 四段流水线、替换正文 mock、本章想法真实入参、生成过渡态→阅读态）→ Story 4.4。本 story 前端**只渲染输入态 UI**（本章想法输入框 + 生成按钮，AC4），**点生成的真实生成逻辑不接**。
