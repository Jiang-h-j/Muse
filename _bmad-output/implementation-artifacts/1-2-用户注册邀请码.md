# Story 1.2: 用户注册（邀请码）

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 被邀请的早期创作者，
I want 用邀请码 + 邮箱 + 密码创建账号，
so that 我能拥有一个隔离的、属于我自己的创作空间。

## Acceptance Criteria

**AC1 — 有效邀请码注册成功（FR1，原型契约）**
- **Given** 我在注册页（`#/register`），邀请码字段必填、密码 `minlength=8`（原型 `prototype/app/app.js:305,307`）
- **When** 我填入有效未使用的邀请码 + 合法邮箱 + ≥8 位密码并提交
- **Then** 系统创建 `user` 记录（密码经 **argon2** 哈希存储，绝不明文），把该邀请码标记为已使用（记录使用者与使用时间）
- **And** 接口返回成功资源体（camelCase，不套 `data` 包装；本 story 不签发 token——登录/会话是 Story 1.3），前端据此按原型行为跳转 `#/projects`（原型 `app.js:1697-1699`，`650ms` 后跳转）

**AC2 — 邀请码无效/已用/过期被拒（原型 `invalid` 文案对接）**
- **Given** 我提交注册
- **When** 邀请码不存在、已被使用或已过期
- **Then** 后端返回统一 error envelope `{code, message, detail}`（HTTP 4xx），响应体附兼容原型的布尔位（`invalid: true`，对接原型注册模式 `invalid` 分支），**账号不被创建、邀请码状态不变**
- **And** 前端呈现注册模式 `invalid` 文案「邀请码无效、已使用或已过期。」（原型 `app.js:262`，经 `stateMessage(state,'register')`）

**AC3 — 邮箱重复冲突（不泄露多余信息）**
- **Given** 我提交注册
- **When** 邮箱已被注册
- **Then** 返回明确冲突 error envelope（如 `code=email_conflict`），不创建重复账号，**不泄露密码/内部细节**；即使邮箱冲突也不得消耗/标记本次邀请码
- **And** 邮箱唯一性由 DB 唯一约束兜底（并发下不产生重复账号）

**AC4 — 后端独立校验，不信任前端（NFR6 安全边界）**
- **Given** 前端做了 HTML5 校验（`reportValidity()`，原型 `app.js:1692`），但可被绕过
- **When** 邮箱格式非法、密码 <8 位、或邀请码为空直达后端
- **Then** 后端独立用 Pydantic 校验并拒绝（返回 `validation_error` envelope，HTTP 422），**不依赖前端校验**
- **And** 校验错误响应经基座既有脱敏处理**不回显 `input` 原始值**（复用 `core/errors.py` 的 `RequestValidationError` handler，避免反射明文密码）

**AC5 — user 表作为多租户根（NFR3）**
- **Given** 需按需建 `user` 表 + `invite_code` 表（本 story 建表范围）
- **When** 建表迁移执行
- **Then** `user` 表结构成为后续 `project`/`byok_key`/`usage_ledger` 的租户根（所有业务数据后续以 `user_id` 行级隔离，NFR3）
- **And** 新表在 `migrations/env.py` 登记导入（否则 autogenerate 检测不到，见 Dev Notes 陷阱②）；`alembic upgrade head` 可正常升级、`downgrade` 可回滚

- **错误 envelope（AR5）**：业务错误抛 `core/errors.py:ErrorEnvelope(code, message, detail, http_status)`；全局 handler 已注册（`ErrorEnvelope`/`HTTPException`/`RequestValidationError`/`Exception` 四类）。**校验错误脱敏已就绪**（`_handle_validation` 剔除 `input`），AC4 直接受益，勿重复实现。

### 关键实现陷阱（务必规避）
- **陷阱①：密码哈希用 argon2-cffi，不是 passlib。** 1.1 review 已把依赖从 `passlib[bcrypt]` 换成 `argon2-cffi`。用法 `PasswordHasher().hash(pw)` / `.verify(hash, pw)`。**绝不明文存储密码**（AC1 硬要求）。
- **陷阱②：新建模型必须在 `migrations/env.py` 登记 import。** `env.py:12-13` 有注释占位「后续 story 建表时在此登记」。不加 `from muse.models import account`，`autogenerate` 检测不到新表**却不报错**，生成空迁移——1.1 review Defer 项已预警。
- **陷阱③：邀请码「校验」与「消费」的原子性。** 校验通过到标记已用之间若非单事务，并发下同一码可能被用两次。用**单事务** + 行锁（`SELECT ... FOR UPDATE`）或「条件 UPDATE 影响行数=1 才算抢到」保证一次性。邮箱冲突/任何失败都不得消耗邀请码（AC2/AC3）。
- **陷阱④：邮箱唯一性靠 DB 约束兜底，不靠先查后插。** 先 `get_user_by_email` 再 `create_user` 存在 TOCTOU 竞态；必须给 `email` 加 DB 唯一约束并捕获 `IntegrityError` 转 `email_conflict`（AC3）。
- **陷阱⑤：本 story 不签发 token、不做登录。** 注册成功仅创建账号 + 前端跳 `#/projects`（原型 `app.js:1697` 就是纯跳转、无 token 逻辑）。JWT 双 token 会话是 **Story 1.3** 的范围，勿越界。

### Debug Log References

- 一处测试失败并非产品缺陷：`test_short_password_rejected_422` 初版哨兵密码 `"short"` 恰是 Pydantic 错误码 `string_too_short` 的子串，脱敏断言误报。改用独特哨兵 `"a1b2c"` 后通过——1.1 的 `input` 剔除机制本就正常工作。
- mypy 报 `Result[Any]` 无 `rowcount`：UPDATE 的 `session.execute` 实际返回 `CursorResult`，用 `cast("CursorResult[object]", ...)` 表达该意图。

### Completion Notes List

- **全 5 条 AC 端到端验证通过**（真机起 FastAPI + 真实 PG 走 curl）：AC1 有效码注册返回 201 + camelCase `{id,email}` 安全视图、密码以 `$argon2id$` 哈希落库无明文；AC2 无效/已用/过期/同码复用均 400 `invalid_invite` + `detail.invalid=true`（对接原型 `app.js:262`）；AC3 邮箱冲突 409 `email_conflict` 且该次邀请码 `used_at` 保持 NULL（不消耗）；AC4 密码<8/邮箱非法/邀请码空均 422 `validation_error` 且响应无 `input` 明文；AC5 迁移建表 upgrade/downgrade 往返通过、autogenerate 能检出新表。
- **邀请码原子消费（陷阱③）**：`mark_invite_used` 用条件 UPDATE（`used_at IS NULL AND (expires_at IS NULL OR expires_at > now())`）+ `rowcount==1` 判定抢到，杜绝并发下同码被用两次；service 内单事务编排，任何失败整体回滚。
- **邮箱唯一性（陷阱④）**：DB 唯一约束兜底，`create_user` 捕获 `IntegrityError` → 回滚 → `email_conflict`；因邮箱预检在消费邀请码之前，冲突时邀请码状态不变。
- **不越界（陷阱⑤）**：本 story 不签发 token、不做登录；`core/security.py` 仅新增 `hash_password`，`verify_password`/JWT 留给 Story 1.3。
- **测试策略**：DB 用例沿用 1.1 的 `MUSE_DB_READY=1` 门禁（离线自动 skip）；conftest 用与应用同 DSN 的**同步**引擎做建表/清表/断言，与应用 async 引擎分属不同连接互不干扰。离线可跑 10 项（含 AC4 校验脱敏），带 DB 共 19 项全绿。
- **质量门禁全过**：`uv run ruff check` / `uv run mypy`（30 files）/ `uv run pytest`（19 passed）。
