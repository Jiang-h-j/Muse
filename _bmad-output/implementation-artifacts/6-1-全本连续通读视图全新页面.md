# Story 6.1: 全本连续通读视图（全新页面）

Status: done

> **Epic 6 背景**：Epic 6 是全项目交付链的最后一段。用户在此拿到「一本真正的小说」——从头到尾连续读完自己的已定稿章节。
> **Story 依赖**：6.1 → 6.2（AI 标识叠加）。前后端一起交付（不走旧「后端先行、前端 later 统一接」节奏）。
> **按需建表**：无（消费 Epic 4 已定稿章节）。
> **说明**：通读视图是全新页面，原型无既有页面（原型最终页仅到 `archive`）。本 story 无现有交互契约可继承，AC 直接来自 FR26 + NFR3 + NFR4。
> **前端路由**：`#/projects/:id/readthrough`（与 Origin `#/projects/:id/archive` / `#/projects/:id/chapters/1` 并列，在作品行「继续创作」后的新 `phase=readthrough` 下）。
> **注意**：通读视图在原型 `app.js:4520-5191` 已有完整线框模板（4520 行 mock 数据 + 5102-5191 渲染+交互），V1 须替换为后端真实数据。本节涵盖「所有已定稿章节」的按序呈现、空态、多租户与跨章分页。

## Story

As a 写完（部分）章节的用户，
I want 从头到尾连续读一遍我自己写的书，
so that 我能以读者视角体验「我写出了一本真正的小说」。

## Acceptance Criteria

**AC1（通读视图入口 + 真实数据路由，FR26）**
**Given** 原型无通读视图页（全新页面，FR26；原型最终页仅到 `archive`）
**When** 我从作品入口（`#/projects/:id/readthrough`）进入通读视图
**Then** 按顺序连续呈现该作品所有已定稿章节的正文（消费 Epic 4 定稿章节），让我从头读一遍自己的书。数据源为后端 `GET /api/projects/:id/readthrough`，返回 `{chapters: [{title, chapterNumber, contentPages, totalPages}], metadata: {totalChapters, hasUnfinalized}}`。**替换原型 4520 行 `readthroughChapters` mock 数据**。

**AC2（连续通读 + 分页阅读，FR26）**
**Given** 通读视图连续呈现
**When** 我阅读
**Then** 已定稿章节按章节编号顺序无缝拼接呈现（从第 1 章到末章，原型 `READTHROUGH_PER_PAGE = 6` 段落/页）。章内翻页（`← / →`）按边界 disabled（首页禁「上页」、末页禁「下页」，原型 `atBookStart`/`atBookEnd` 判据）。跨章翻页规则：
- 翻过本章末页 → 进入下一章第一页（原型 `readthroughPageIndex < pages.length - 1` → `readthroughChapterIndex += 1, pageIndex = 0`）
- 从本章首页往回 → 回到上一章末页（原型 `readthroughPageIndex > 0` → `readthroughChapterIndex -= 1, pageIndex = lastPage`）
- **跨章持续**：当处于章末页（`readthroughPageIndex === pages.length - 1`）点「下页」时，切换到下一章第 0 页；反之亦然

**AC3（只读、聚焦阅读体验）**
**Given** 通读视图连续呈现
**When** 我阅读
**Then** 页面只读、聚焦阅读体验——不提供批注/编辑/修改入口（区别于 Epic 4 单章分页创作视图）。原型 `readthrough-reader` 的 `<article aria-live="polite">` 容器保持语义。不显示原型 `readthrough-title-select` 中的选择器（`<select>` 章标题选择器，原型 `readthrough-chapter-title` + `readthrough-title-caret`），代之以纯读章节标题行。

**AC4（数据多租户隔离，NFR3）**
**Given** 数据多租户隔离（NFR3）
**When** 我打开通读视图
**Then** 只呈现属于我（当前 `user_id` + `project_id`）的已定稿章节。若 API 返回 `userId !== currentUserId` 则过滤（或在 API 层直接按 token 过滤）。不报非本人数据错误。

**AC5（只有已定稿章节进入通读，与 Epic 4 定稿态一致）**
**Given** 只有已定稿章节进入通读（与 Epic 4 定稿态一致）
**When** 某章尚未定稿
**Then** 未定稿章节不进入通读视图（通读是「已完成的书」的视图）。后端 API `GET /readthrough` 自动排除 `chapter_finalized=false` 的章节（由 `chapter_service.list_finalized_chapters` 过滤，替代前端过滤）。

**AC6（空态——尚无任何已定稿章节）**
**Given** 作品尚无任何已定稿章节
**When** 我进入通读视图
**Then** 呈现合理空态提示：
- 头部「暂无通读内容」提示 + `explore-back "← 故事档案" 保留
- 标题区「还没有可通读的已定稿章节，继续创作吧」
- 不报裸错、404 或空白页
- **与作品库 `empty` 空态区分**：作品库 `empty` 是「没有作品」；通读 `empty` 是「有作品但无已定稿章节」。前者走 `empty-library` 完整空态，后者走 `readthrough-empty` 轻空态。

**AC7（通读视图数据结构）**
**Given** 通读视图加载
**When** 数据就绪
**Then** 数据结构为：
```json
{
  "chapters": [
    {
      "chapterNumber": 1,
      "title": "第 01 章标题",
      "pages": ["<p>段1</p>", "<p>段2</p>", ...],  // READTHROUGH_PER_PAGE=6 段/页
      "totalPages": 3  // 由后端按 READTHROUGH_PER_PAGE 分页
    }
  ],
  "totalChapters": 5,
  "hasUnfinalized": false  // 是否存在未定稿章（纯后端判断，不阻塞）
}
```
- `pages` 数组每元素是 `READTHROUGH_PER_PAGE` 段的分页
- `totalPages` 由 `chapter_content.length / READTHROUGH_PER_PAGE` 向上取整
- 前端直接渲染 `pages[pageIndex].map(p => <p>${p}</p>)`，不做二次分页

## Dev Notes

### 本 story 性质：全新页面 + 消费既有数据

Story 6.1 是**全项目唯一纯消费型 story**——不需要建新表、不需要新增编排、不需要新 provider、不需要新存储。它只做一件事：**把 Epic 4 已定稿的章节拿过来，按顺序呈现出可读的书**。

**核心改动量**：
1. 后端：新建 `routers/readthrough.py`（~50 行）+ `schemas/readthrough.py`（~40 行）+ `chapter_service.list_finalized_chapters`（~20 行）
2. 前端：改造 `renderReadthrough()`（~80 行）+ `bindReadthroughInteractions()`（~50 行）+ 数据源替换（~20 行）
3. 测试：后端（~60 行）+ 前端（~80 行）+ 多租户（~30 行）

**此 story 前 4-5 个完成度**：Epic 4 已全部 done（4.1–4.7 完整），定稿章存在且可读。

### 前端型态

通读视图是**非交互式只读页**——没有批注、没有编辑、没有反馈、没有段落评论。所有用户操作是：
- 选择章（`<select>` 章选择器）
- 翻页（`← / →`）
- 阅读正文

与 Epic 4 创作视图的**核心区别**：
| 维度 | 创作视图（4.4） | 通读视图（6.1） |
|------|-----------------|-----------------|
| 数据源 | 生成中/待定稿 | 已定稿 |
| 交互 | 可批注、可编辑、可反馈 | 只读 |
| 章节状态 | `input/generating/reading` 三态 | `readthrough/ready` 单态 |
| 路由 | `#/projects/:id/chapters/1` | `#/projects/:id/readthrough` |
| 页内锚点 | 分页阅读（锚点式） | 连续通读（跨页式） |
| 空态 | 无 chapter 时的生成态 | 所有章节均为空/无定稿 |

### 原型到 V1 的迁移

**原型 `readthroughChapters`（4520 行）**：3 章 mock 数据（`"打破日常" / "不存在的证明" / "代价显现"`），每章 `paragraphs` 数组 6-8 段。`renderReadthrough` 将其渲染为分页通读页。

**V1 替换**：3 章 mock → 后端 `GET /api/projects/:id/readthrough` 返回的真实已定稿章节。阅读体验保持原型 `readthrough-reader` 的 `readthrough-wrapper` 结构不变，数据格式转为 `{chapters: [{chapterNumber, title, pages, totalPages}], ...}`。

**READTHROUGH_PER_PAGE 是定数**（在 `prototype/app.js` 中 `const READTHROUGH_PER_PAGE = 6`）。通读视图每页 = 6 段。章内分页 = `content.length / 6` 向上取整。与通读视图的唯一交互是「翻页」——不提供分页大小调整。

### 翻页交互（与创作视图一致）

通读视图使用与 Epic 4 创作页一致的 `←/→` 翻页模式：
- `data-readthrough-page="previous"`（←）和 `data-readthrough-page="next"`（→）
- `atBookStart = chapterIndex === 0 && pageIndex === 0` → `← disabled`
- `atBookEnd = chapterIndex === lastChapter && pageIndex === lastPage` → `→ disabled`
- 翻过章末页 → 进入下一章（跨章）
- 翻回首页 → 回到上一章末页（跨章）

### 通读视图为空时

当 `readthroughChapters 为空` 时 → 展示通读空态。不报错、不 404。展示「还没有可通读的已定稿章节」。不阻塞进入下一章/回到归档页。

### 陷阱清单

**陷阱①：通读视图的「向前」翻页不重置页面标题。** `renderReadthrough` 中原型 `document.title = "通读 · ${chapter.title} · Muse"` 保持不变，跨章翻页时不重新设置——V1 保持此行为（通读不改变 `document.title`，让 `render()` 统一管理）。

**陷阱②：通读视图的「章选择器」不可用作路由跳转。** `readthrough-chapter` 选择器的 `change` 事件仅更新 `readthroughChapterIndex` 并触发 `renderReadthrough()`，不改变 URL hash 路由。V1 保留此行为（通读是「书内」视图，不在 hash 路由层）。

**陷阱③：通读视图的「←」翻页不可触发历史倒退。** 通读页面的 `←` 按钮是页面内翻页（`data-readthrough-page="previous"`），不是浏览器历史回溯。`event.preventDefault()` 在 `bindReadthroughInteractions()` 中已做。V1 不改变此行为。

**陷阱④：跨章翻页后，当前页的「←」和「→」语义与前后章不同。** 当用户在新章首页（`readthroughPageIndex === 0`）时：`←` 到达上一章末页，`→` 进入本章第 1 页。不是「上一页/下一页」严格对应关系。V1 保持此交互。

**陷阱⑤：通读视图是纯只读视图——无任何修改入口。** 通读页面的 `readthrough-chapter-title` 不显示编辑按钮、不提供修改入口、不提供删除/重命名。V1 保持此只读属性。

**陷阱⑥：第六章已有已定稿章节时，通读页面的「←」回到首页（`readthroughChapterIndex = 0`）不应触发回到上一章。** 当用户处于第 1 章第 1 页且 `readthroughChapterIndex === 0 && readthroughPageIndex === 0` 时，`←` 应 disabled——不进入上一章（无「上一章」）。V1 保持 `atBookStart` 判据。

**陷阱⑦：「通读」和「阅读」的不一致性**。通读视图的「←/→」翻页是「上一页/下一页」翻页模式——在通读中「翻过本页末页」是「进入下一章第 1 页」，「翻过本章首页」是「进入上一章末页」。而 Epic 4 的「分页阅读」是「按页翻阅，翻过末页翻回首页」。通读视图的翻页是「翻页」而非「循环」，而 Epic 4 的翻页是「循环」（第 1 章末页→第 2 章首页）。两者不一致，但通读视图保持原型行为。

**陷阱⑧：通读视图的跨页数据格式**。后端 `list_finalized_chapters` 返回的章节正文是一个平面 `content` 数组（每项是一段文本），不是分页后的 `pages` 数组。前端 `renderReadthrough` 需要将 `content` 按 `READTHROUGH_PER_PAGE = 6` 分页。后端 schema 中 `totalPages` 由 `len(content) / READTHROUGH_PER_PAGE` 向上取整。

**陷阱⑨：通读视图的章跳转。** 通读视图的「章选择器」是下拉 `<select>`（`data-readthrough-chapter`），不是按钮跳转。`readthrough-chapter-title` 的 `<h1>` 下方有一个 `<span class="readthrough-title-caret">▾</span>` → `<select>` 在其下方。选择器显示「第 NN 章 · 标题」，选择「第 1 章」或「第 2 章」等。

**陷阱⑩：并行渲染问题。** 未定稿章节不进入通读视图（后端过滤）。一个作品可能有 5 章定稿 + 3 章未定稿 → 通读视图只显示 5 章。`hasUnfinalized` 只用于信息展示（「还有 X 章即将完成」），不阻塞阅读。

**陷阱⑪：`hasUnfinalized` 在后端不应是 404 的充分条件。** 通读视图的 `hasUnfinalized=true` → 只告知「还有未定稿章节」，不阻断通读渲染。空态 `hasUnfinalized=false && totalChapters=0` → 通读空态（「还没有可通读的章节」），不 404。

**陷阱⑫：通读视图的「新」页面不「新」路由。** 通读视图是全新页面但路由不是全新的——`#/projects/:id/readthrough` 复用原 `#/projects/:id/projects` 的 hash。`render()` 需要识别 `readthrough` 并跳转到通读页。如果不在 `readthrough` 路由则正常绘制作品页。
