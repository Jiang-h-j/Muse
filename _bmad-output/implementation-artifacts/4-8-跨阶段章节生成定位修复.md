# Story 4.8: 跨阶段章节生成定位修复

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 已完成第 1 阶段、正进入第 2 阶段继续写章的用户，
I want 跨阶段后第 3 章及之后的章节也能正常生成/改进，
so that Epic 4 阶段循环（Story 4.7 落地）真正走得通，我写的长篇不会被卡在首阶段末尾。

## 背景与根因（已定位，直接采用，勿再调研）

Epic 4 阶段循环（Story 4.7）落地后，跨阶段章节生成路径走不通——这是 Story 5.3 code review 时登记的 deferred bug（`deferred-work.md:13-15` 5.3 段第 1 条），现决定正式修复归 Epic 4 的 Story 4.8。

**Bug 现场**（`backend/src/muse/services/chapter_service.py`）：
- `trigger_chapter_generation` 第 342-347 行
- `trigger_chapter_revision` 第 415-420 行

两处都用 `stage_plan_repo.get_stage_plan(session, user_id=..., project_id=...)`——**不传 `stage_number`，默认 1**——只取第 1 阶段规划，再把**全局连续** `chapter_number` 跟第 1 阶段的 `chapters` 长度比：

```python
stage_plan = await stage_plan_repo.get_stage_plan(session, user_id=..., project_id=...)
chapters = (stage_plan.chapters if stage_plan else None) or []
if chapter_number > len(chapters):
    raise _chapter_out_of_range()
```

**触发场景**：第 1 阶段 2 章 → 用户定稿末章 → 进阶段交界 → 触发第 2 阶段规划出 3 章 → 现在生成全局第 3 章（第 2 阶段第 1 章）→ `3 > 2` → 抛 `chapter_out_of_range` 400。**跨阶段后所有第 3+ 章无法生成/修订，Epic 4 阶段循环实际走不通。**

**修法（5.3 defer 条目已指明方向）**：
- 用 `stage_plan_repo.locate_stage_for_chapter()`（Story 5.3 已实现，stage_plan_repo.py:95-120，按累计章数定位全局章号落在哪个阶段，无匹配返回 None）替代 `get_stage_plan()`。
- `finalize_chapter`（chapter_service.py:597-611）已经这么用了——**生成/修订路径是漏改**，本 story 把两处补齐对齐 finalize 的范式。

## Acceptance Criteria

1. **`trigger_chapter_generation` 跨阶段定位（AC 草拟 1）**：用 `stage_plan_repo.locate_stage_for_chapter(session, user_id=..., project_id=..., chapter_number=...)` 按全局章号定位所属阶段。判定规则改为：
   - `chapter_number < 1` → 抛 `_chapter_out_of_range()`（语义不变）
   - 作品尚无任何 `stage_plan`（连首阶段都没规划）→ 抛 `_chapter_out_of_range()`（**沿用 4.4 现有行为**，契约测试 `test_generate_no_stage_plan_returns_400` / `test_revise_no_stage_plan_returns_400` 已钉死）
   - `locate_stage_for_chapter` 返回 None（有规划但目标章超出全部规划累计章数）→ 抛 `_chapter_out_of_range()`
   - 否则放行（不再做阶段内长度比对，定位本身即边界）

2. **`trigger_chapter_revision` 同步改造（AC 草拟 2）**：规则与 AC1 完全一致——同一段范围校验代码替换为 `locate_stage_for_chapter` 范式。修订路径下的「本章须已有正文」前置（`_chapter_not_generated`，chapter_service.py:436-437）**不变**——未生成章节仍然 400 `chapter_not_generated`（语义不变）。

3. **跨阶段端到端回归测试（AC 草拟 3）**：新增 `@requires_db @requires_redis` 集成测试（建议放 `backend/tests/test_chapter_generate_api.py` 或新文件 `test_chapter_cross_stage.py`，dev 择优）——构造两阶段 stage_plan（第 1 阶段 2 章 + 第 2 阶段 3 章，全局共 5 章），断言：
   - 全局第 3、4、5 章调 `POST .../chapters/{n}/generate` 均**不再 400**（返 200 + taskId）
   - 全局第 6 章（超出第 2 阶段末章）仍 400 `chapter_out_of_range`
   - `chapter_number=0` 仍 400 `chapter_out_of_range`（负数由路由 int 转换器 404，无需测）
   - 每次 400 时 `register_task_owner` 不被调用（沿用现有 `spy_register.assert_not_awaited()` 范式）

4. **修订路径跨阶段回归（AC 草拟 4）**：同款两阶段 stage_plan 夹具下：
   - 对全局第 3 章先种子 `chapter` 行（status=draft）→ 调 `POST .../chapters/3/revise` 不 400（200 + taskId）
   - 对全局第 4 章（无 chapter 种子）调 revise → 400 `chapter_not_generated`（沿用现有行为）
   - 对全局第 6 章（越界）调 revise → 400 `chapter_out_of_range`
   - 已 finalized 章（status=finalized 种子）调 revise → 400 `chapter_already_finalized`（沿用 4.7 review patch F1甲）

5. **首阶段行为零回归（AC 草拟 5）**：原有单阶段作品（仅 stage 1）全链路不回归——
   - 跑通既有测试套件即视为兑现：`MUSE_DB_READY=1 MUSE_REDIS_READY=1 uv run pytest -q` 全绿零回归
   - 重点核对既有用例：`test_chapter_generate_api.py::test_generate_out_of_range_returns_400`（首阶段 3 章造第 4 章 → 仍 400）+ `test_generate_no_stage_plan_returns_400` + `test_chapter_revise_api.py` 同族用例
   - 既有 `_chapter_out_of_range` 错误码语义（前端 `storyErrorText` 已按此 code 出文案，app.js:794-802）**不改**

### 推荐的修复代码范式（供 dev 直接照抄）

```python
# 章号范围校验（防御 API 直打，Story 4.8 跨阶段定位）：
# chapter_number 须 >= 1 且落在**全部**阶段规划的累计章数范围内。
# 无阶段规划（连首阶段都没生成）时也拦——不给「阶段规划都没有」的作品排生成任务。
# locate_stage_for_chapter 内部对 chapter_number<1 / 无规划 / 越界均返 None，
# 为保持 4.4 契约（无规划也抛 chapter_out_of_range），None 时不再细分原因。
if chapter_number < 1:
    raise _chapter_out_of_range()
target_stage = await stage_plan_repo.locate_stage_for_chapter(
    session, user_id=user_id, project_id=project_id, chapter_number=chapter_number
)
if target_stage is None:
    raise _chapter_out_of_range()
```

⚠️ **设计决策（已核实既有契约）**：
- **「无 stage_plan」与「越界」合并抛 `chapter_out_of_range`**——沿用 4.4 既有行为（现有 `test_generate_no_stage_plan_returns_400` 已钉死此契约），**不另设 `no_stage_plan`**。`_no_stage_plan` 工厂（chapter_service.py:212）只用于 `trigger_next_stage_planning`（4.7 AC5），本 story 不动它。
- **finalize_chapter 的「无规划兼容落 stage 1」分支（chapter_service.py:604-609）不搬到本 story**——那是 finalize 为兼容「旧作品有 chapter 无 stage_plan」的特殊路径；生成/修订是从零跑流水线，不应有此兼容（4.4 既有契约即「无规划拒生成」）。
