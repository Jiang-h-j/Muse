# Story 4.4: 本章想法输入 + 真实生成章节正文

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 要写某一章的用户，
I want 可选地补充本章想法、然后让 Agent 依设定和上下文真实写出这一章，
so that 我既能引导本章走向、也能零负担地直接生成。

## Acceptance Criteria

1. **真实生成替换 mock（AR19 门禁前置）**：盲测已通过（4.1 GATE=PASS，创始人 2026-08-04 放行，deferred-work.md:336）。本 story 用户点「生成」时**真实调用 4.2 四段流水线**（`pipeline.run_chapter_pipeline`）生成章节正文，替换原型 1200ms `setTimeout` mock + `generatedChapterMarkup` 硬编码 3 页（app.js:3138-3142 / 2937-2967）。

2. **本章想法可选填（FR18，UX-DR7）**：输入态（`chapterCreationState="input"`）下「本章想法」标「可选」、placeholder「可以补充想看到的场面、人物表现、节奏或一句具体的对白……」（app.js:3078-3079）；可留空。

3. **提交与状态流转**：按钮文案随输入切换「生成本章」（有想法）/「跳过并生成」（空，app.js:3080/3120-3121）；点击后 `input→generating→reading`（`chapterIdea` 空/非空决定文案，app.js:3127-3128）。

4. **写前上下文组装（AR16，context-agent，FR18）**：`context-agent` 消费「全量设定 + 最近前序章节正文」直接注入 drafter（RAG 三级召回 + 归档卡片属 Epic 5，epics.md:859③）。填补 `steps.py:108-110` 预留的「最近定稿章节注入点」TODO——从新建的章节正文业务表读前序章节正文注入。**V1 注入最近 draft 前序章节**（4.7 定稿未实现前唯一能保证多章连续性的做法，Jianghj 2026-08-05 决议，见 Dev Notes）。

5. **生成过渡态（NFR2 异步）**：`generating` 态显示「正在写下这一章」+ 据 `chapterIdea` 动态插入「和你的本章想法」（app.js:3087-3088），经 SSE `progress` 推进度、收到 `result` 后转 `reading` 态并渲染真实正文。走 4.2 已建异步任务模型（`POST→taskId→GET /api/tasks/{taskId}/events` SSE），不同步阻塞、不前端轮询。

6. **正文落业务表 + 重进恢复**：生成的正文落**新建的章节正文业务表**（deferred-work.md:342 明确「正文落业务表全留 4.4」）；刷新/断线重进第一章能读回已生成正文（GET 恢复），无需重生成、不重复付费（NFR5）。已在途生成的任务凭本地 taskId 接回 SSE（仿 4.3 `consumeStagePlanTask`）。

7. **失败与守卫**：生成失败（护栏 429 / 空产 502 / 泛化 `generate_failed`）经 SSE `error` 事件回前端，退回可重试态、给可读提示（复用 `storyErrorText`）。租户越权/不存在作品 → 404 二义合一（NFR3）；未确认设定 → 400 `bible_not_confirmed`（防御）。

8. **ARQ 硬化（兑现「归 4.4」defer）**：`generate_chapter` 确定性失败不再被 ARQ 默认重试 5× 重复付费——设 `max_tries` + 终态幂等守卫（deferred-work.md:112/162/215）。
